# 测井面板的网络相预测

打开测区井的测井预览或辅助资料中的综合柱状图，工具栏提供模型选择、
「预测相」「停止等待」「显示预测相」「刷新模型」「预测服务」。
参考井不需要关联测区井号或井位坐标即可运行相预测。

首次使用在「预测服务」填入服务地址和 API 密钥。**没有缺省地址**（#133：
不再硬编码任何第三方地址），请向服务提供方索取正式地址。

2026-10-20 预测专项：#598 曾把一个服务地址与 API 密钥明文写进
`WellFaciesConfig::load()` 作兜底，已撤除——**源码与安装包不再携带任何 API
密钥**。打包机若需要开箱即用的缺省地址，在本地配置期给出（不入库）：

```bash
cmake -S . -B build -DPALEO_WELL_FACIES_DEFAULT_URL=https://facies.example.org/api/v1
# 仅当该缺省地址确为内网 http 时再加：-DPALEO_WELL_FACIES_DEFAULT_ALLOW_HTTP=ON
```

密钥仍须由用户在「预测服务」填写（钥匙串）或经 `PALEO_WELL_FACIES_API_KEY`
提供；未配置密钥时面板如实显示「请在「预测服务」配置 API 密钥」。曾经入库的
那把密钥已随公开仓库历史暴露，**须由服务维护者轮换**（本仓库改动无法替代轮换）。

传输安全（#133）：

- 只接受 `https://`。`http://` 仅对本机回环（`localhost` / `127.x` / `::1`）
  放行，便于本地调试服务。
- 内网只有 http 的部署，须在「预测服务」勾选「允许不加密的 HTTP」（或设
  `PALEO_WELL_FACIES_ALLOW_INSECURE_HTTP=1`）——此时 API 密钥与整井曲线明文
  过网，状态栏给出警告。不建议用于公网地址。
- 不跟随重定向；响应体超过 64 MiB 即中止。

密钥存储：

- 构建找到 Qt6Keychain（QGIS 的既有依赖；Linux 装 `qtkeychain-qt6-dev`）时，
  密钥存入系统钥匙串（Windows 凭据管理器 / Secret Service(libsecret、KWallet) /
  macOS 钥匙串），`~/.config/paleo/well-facies.json` 只存地址与开关；旧版 JSON
  里的明文密钥在首次启动时自动迁入钥匙串并从 JSON 删除。
- 构建未带 Qt6Keychain，或钥匙串写入失败时，回落为 JSON 明文存储：POSIX 下
  权限 0600（仅当前用户可读写）；**Windows 下文件权限不提供同等保护**，请依赖
  用户目录 ACL，或改用环境变量。
- 也可用 `PALEO_WELL_FACIES_URL`、`PALEO_WELL_FACIES_API_KEY` 环境变量覆盖
  （环境变量里的密钥不会写入钥匙串或文件）。`PALEO_WELL_FACIES_NO_KEYCHAIN=1`
  可关闭钥匙串（ctest 沙箱默认设置）。`PALEO_WELL_FACIES_CONFIG` 可把配置文件
  挪到指定全路径（Windows 上配置目录是 `%LOCALAPPDATA%`，不受 `XDG_CONFIG_HOME`
  影响；测试与便携场景用它隔离真实配置）。

模型要求从 `GET /models` 获取。**预测按地层组进行**：井上每个有模型的地层组
各提交一次，模型取 `formationGroup` 与该组一致的那个（同一地层组有多个模型
版本时用工具栏所选版本，否则取列表首个）。每组各自检查曲线、段、岩性、
连续深度和窗口点数；某组输入不可用只跳过该组，原因写进状态行，不拖累其他组。
井上有地层组却没有对应模型的，标「无对应模型」并跳过，不拿别的模型去预测它。
井上没有标注地层组、或没有任何组命中模型时，沿用整井口径：只用所选模型预测
它能用的井段。全部不可用时面板和 tooltip 给出所选模型的具体原因。
段来自实际段分层，不能以组替代；岩性来自岩性井道。
曲线按模型字段名匹配（忽略大小写），不将其他曲线自动当成 GR。
不同采样网格只在有效曲线端点之间作线性插值，不外推、不补缺失值。
每组只提交该地层组的连续井段，不把整井当作目标组；各组井段不得重叠
（重叠的后一组跳过，所选模型所在的组优先）。

`POST /predict` 每个地层组一次，使用该组模型版本 ID；各组**顺序**提交、逐组返回。
200 完成后展示结果；202 按服务的 `pollAfterMs` 查询 `GET /predictions/{jobId}`，
不会重新提交。网络操作采用 Qt 异步请求，HTTP、非法 JSON 和 failed/canceled
状态均显示原因。轮询固定在配置的服务地址下，不向响应内的其他主机发送密钥。
「停止等待」停止客户端请求并放弃所有尚未返回的地层；服务端没有取消 API，
已受理任务会继续执行。已受理未终态的任务按「模型 + 井 + 该组输入」记住任务 ID，
停止后再点预测会继续查询在途地层，不重复提交。

每个地层组一返回，就并入预测相道显示并按组缓存；全部地层走完后一次性回写
属性（某组失败时已返回的各组照常保存）。完成后新增独立「预测相」三级组合道（相 / 亚相 / 微相）和
「预测置信度」曲线道（0–100%），不改写原有相解释。显示开关同时控制这两道，
井道的现有导出能力可输出结果。
每组的完整响应以模型、服务、井名和该组实际输入内容的 SHA-256 为键保存到本机
`~/.local/share/paleo/well-facies/`；重新打开相同数据会逐组恢复并合并结果。
换井、切模型或修改输入时清理旧结果，避免把上一口井的预测留在当前井。

优势相：每个地层单位（井地层道里的组、段，各出一行）取累计厚度最大的预测相作为
该地层的预测结果相——例如地层厚 100 m、分流河道累计 60 m，优势微相就是分流河道
（占比 60%）。综合图在「预测相」「预测置信度」之外新增「优势相」道（组、段两级都有时
为「优势相（组）」「优势相（段）」两道，文字 =「优势微相 占比」，并列时加注），显隐开关
与预测相共用。全部地层走完后，优势相与井段一起回写「地层优势相」矢量表
（`welllog.formations`，井点要素、每井每地层一行，可在属性表里维护 `dominant_facies`
等列），测井页「地层优势相属性」按钮打开它。智能预测的测井预测写同一张表，两边数据
相通，字段与规则见 [测井与单因素的矢量属性维护](WELL_VECTOR_ATTRIBUTES.md)。

进度：每个地层组是任务中心（底栏「任务」页）里的一条任务——进度条取服务端上报的
进度，状态为运行中 / 完成 / 失败（带原因）/ 已取消，进入即排队可见。任务启动时
数据页会自动露出底栏任务页。任务页「取消」只放弃该地层（排队中的轮到时跳过），
其余地层照常提交；工具栏「停止等待」一次放弃全部。任务由 `PaleoTaskService`
的外部驱动任务（`beginExternal`）承载，不占线程池；未注入任务服务时只走状态行。

实现分层：`domain/welllogfacies` 校验输入/结果、按地层组出预测计划
（`planWellFaciesRuns`）与合并逐组结果（`mergeWellFaciesResults`）；
`ai/wellfaciesservice` 负责 API 2.0 传输；`workflow/wellfaciesworkflow` 编排逐组
顺序执行、缓存与任务中心任务；`ui/wellcomposite` 发出意图并渲染；
`app/main` 注入功能层工厂（含任务服务）。

测试：`ctest --test-dir build -R 'wellfacies|wellcomposite|layering' --output-on-failure`。
`tst_wellfacies` 默认使用本地 HTTP 服务器，不调用外网。
`PALEO_WELL_FACIES_TEST_XML` 可指定真实综合柱状图来检验输入；另设
`PALEO_WELL_FACIES_LIVE=1` 才执行该井的真实网络推理。
若同时指定 `PALEO_WELL_FACIES_SCREENSHOT`，可保存面板截图；未开启 LIVE 时
截图使用本地测试服务器的结果，日志会明确标注该来源。

批量验证本机的 XML 综合柱状图（不上传原始资料、不调用外网）：

```sh
QT_QPA_PLATFORM=offscreen \
PALEO_WELL_FACIES_TEST_DIR=/path/to/xml-directory \
PALEO_WELL_FACIES_TEST_REPORT=/path/to/report.json \
build/tst_wellfacies realReferenceDirectory
```

逐口输出井名、可用状态、有效点数和不可用原因；对两种井入口检查按钮状态。
符合条件的井通过本地 HTTP 测试服务验证预测道和置信度道的显示。
测试目录和报告路径均为可选配置，未提供目录时跳过批量测试。
