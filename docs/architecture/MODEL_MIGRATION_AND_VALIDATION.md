# 统一模型的迁移与验收

状态：2026-11-06 待实施计划。本次只交付设计文档，不关闭下面任何代码改造项。
前置阅读：[统一模型](UNIFIED_DOCUMENT_MODEL.md)、[I/O 契约](FILE_MODEL_IO_CONTRACTS.md)。

## 1. 迁移原则和不变量

1. 原始资料只读；新块、索引、数据库和预览放工程受管目录或本操作私有 staging。
2. 保留现有 Document/Source/Object ID、CatalogVersion、历史方案及解释数值；改名、重排
   或搬迁不重编号。旧 quick 指纹保持原算法，不伪造完整内容哈希。
3. 每个迁移模块有独立 schema/capability 版本、显式迁移与失败恢复。只读开库不升级，
   未知未来格式拒绝写；升级中断不留下被声明为完成的半份模型。
4. 既有 Catalog 内的人工实体、主选、备注、版本关系是权威决定，不能当作可丢缓存。
   先迁移到规范化控制表，再把兼容投影定义为可重建；同一决定只允许一个权威写口。
5. 对象修订 token 与历史值版本用不同类型/API。无法重放的历史记录如实标注缺失能力。
6. 新旧读口共用领域校验。不能为了兼容保留无上限、按首条回退、猜单位或默认物理基准。
7. QGIS/GDAL 空间操作仍经现有 QGIS 封装；不在新模型里再造 GIS 引擎。

## 2. 批次、依赖和完成条件

批次以验收条件推进，不承诺未经估算的日历工期。M0 可先独立修复；M2 的目录分页和
局部读取可在兼容引用适配器上开展，不必等全部通用地质模型完成。

| 批次 | 内容与预期落点 | 必须先通过的条件 |
|---|---|---|
| **M0：当前高风险边界** | SF3P 页目录按需读、缓存 key 使用持有的 header/显式代次；旧整库替换前的 model-generation CAS、持久意图和旧库保留 | 只看小窗不分配全目录；同路径/大小/mtime 不变但代次不同不串页；并发领域编辑不被旧快照覆盖；跨库故障能恢复 |
| **M1：控制与变化基础** | 规范化 doc_binding/operation；稳定身份别名；SDK generation、事务级 change_log/receipt、可重放元数据 image、文档 watermark；真实井身份声明 | 完整 Context 槽位内主选唯一；旧 scope/typed v1 不误升级；相同 raw 换 parser 可并存；连续提交后仍能重放投影；所有写入口均产生有效事件或明确保守失效 |
| **M2：真正有界的 I/O** | 曲线共享轴/数值块；层位 keyset 与既有索引计划验证；流式 ChunkSink/spill；统一资源账本、ReadCut/Lease、批量查询 | 小窗读量随命中块变化；晚页不随 offset 线性增加；慢首文件/慢消费者仍受预算；取消后释放所有 claim |
| **M3：通用地质语义与依赖** | Well/Wellbore/claim、Axis/Datum/Transform、多体系 Unit/Boundary/Occurrence、分段时深、facet/负依赖索引 | 非四层、重复出现、缺失/尖灭/未钻穿可表达；不猜单位/同名身份；同 ID 更新、无数据变有数据均能正确失效 |
| **M4：版本化值与低放大发布** | 追加 ObjectVersion/manifest、编辑新块/补丁；常规导入 staging+head 切换，退掉全库 clone 发布 | 历史值可读或能力明确缺失；小编辑写量与改动块相关；无跨库半状态；GC 不删任何被任务/历史引用的块 |
| **M5：视图与旧入口收口** | Source/WellTrack/Relation/Seismic/Result 投影与增量订阅；专业 store 按引用适配 | 每视图只提交意图和渲染；不自己拼 scope/找文件/维护第二份主选；切换方案和工程不接收过期结果；旧入口调用计数归零 |

每批分别提交主仓/SDK 配套 PR，保持可回退的读路由。新顶层模块按仓库脚手架登记；
分层、文件/函数规模、QGIS 散布与传递依赖基线只缩不涨。

## 4. 数据迁移协议

### 4.1 控制表规范化

记录旧 Catalog 基底和模块版本，在事务内建立 doc_* 表、旧键→新键映射及迁移凭据。
读取旧 saved bindings 时保留 ID、scope、decision、primary、证据及 revision；typed v1
继续走严格解析。未知 schema 留为不可编辑对象并报原因，不降级为确认后的旧记录。

先影子读取并比较新旧查询，再一次切换该类决定的写权威；禁止长期双向双写。
兼容 links 与文件级主选同 Catalog 事务维护。历史重复 confirmed-primary 不靠数据库
随机顺序裁决，生成候选/冲突待处理；迁移报告不能用“行数一致”替代选择语义一致。

### 4.2 井归属和解析批次

旧 wellId 建 legacy alias 与未细分井筒，保留原归属证据。按名称曾被合并的对象不自动拆分，
也不升级为已确认身份；由来源声明与 IdentityResolution 支持后续 merge/split。
merge/split 创建新的映射修订，历史输入继续指向原固定归属，不改历史数值。

同文件更换适配器、模板或列映射生成新 ImportRun；CatalogVersion 的旧 sourceId 映射
不能就地改成新解析结果。相同字节可共用受管载荷，地质解释和人工修订分别保留。

### 4.3 数值块与历史

按对象、按请求或显式批量任务做惰性物化，不要求打开旧工程先迁移所有数组。
当前值先生成同精度块和 manifest，逐点/质量/轴/空值一致性通过后才切读取路由。
迁移清单标记可复现、仅当前可读或输入缺失，不将 counter 写成历史值版本。

回退是切回兼容读路由及对应已知 schema；已生成的不可变块先保留。
若新语义无法无损表示成旧格式，旧客户端只读/明确拒绝编辑，不逆迁移时悄悄丢字段。

### 4.4 GC 与恢复留存

GC 根包括当前 heads、保留历史版本、FrozenInputManifest、运行 lease、未完成操作和
导出/发布版本。区分受管块与外部原件；GC 永不删外部来源。
先标记候选、宽限期后复核引用再删除；并发创建/固定引用与 GC 由事务/代次隔离。
清目录不能越过尚未消费日志的投影水位。长历史、离线工程及日志保留设置要有容量报告，
不能无限保留却称存储成本不增长。

## 5. 功能与失败验收矩阵

每个数字预算和性能承诺都绑定具体测试入口、数据生成方式与观察指标。

| 场景 | 必须验证的行为 |
|---|---|
| 同名多对象/同名异井 | 按实际 ID/归属取到第二份不同数值；名称只产候选，不能取第一条 |
| 多来源/多用途/多目标 | Context/井筒/方案修订隔离；同井同角色 A@r1 与 B@r1 可各有主选，A 内重复主选拒绝；未裁定 claim 可登记并查看原值 |
| 引用跟随模式 | pinned-value 固定 R1/v1 不受 R2 主选或 R1/v2 影响；follow-object-head 仅随 R1 的相关修订；follow-selection 同时复核用途选择和选中对象修订；冻结值不被改写 |
| parser/profile 改变 | 相同原始字节生成独立解释；旧版本映射和人工编辑保留 |
| 原件搬迁/离线 | 位置更新不改数值身份；已入库/已冻结值可用；弱匹配不冒充强内容一致 |
| 物理语义 | 未知轴/单位/零点/基准拒绝相应换算；保留合法负数；OWT/TWT、符号和 offset 仅应用一次 |
| 多井筒/重复穿层 | 不凭后缀猜井筒；同一单元两次 occurrence 分开读，中间其他单元/gap 不被 MIN/MAX 合窗带入；倒转、断层/未钻穿独立表达 |
| 通用层序 | 0/2/5/几十子单元、非齐层级、显式 n:m 映射与聚合；旧四层 ID/修订/结果不重算 |
| 分段时深 | 重叠/间隙/不连续/重复 MD/多解逆变换；不静默排序丢点、拼表或外推 |
| 同 ID 更新 | 时深语义、层位点、曲线质量、体采样更新均命中真实消费者；仅重绑 ID 的指纹不够 |
| 负依赖 | 原先无拾取/无关系的支持域新增数据也触发复核；包含插值外扩范围 |
| 快照/游标 | 翻页中插入/删除/更新、代次替换、lease 到期；旧一致切面或明确过期，不拼接新旧页面 |
| 旧层位排序 | 重复 seq 用 id 稳定断点；NULL seq 的旧记录独立分区分页不遗漏；验证既有 horizon_order 计划后才决定是否改索引 |
| 领域并发提交 | 准备期间另一写者提交后，旧 expectedModelHead 失败，较新用户修改保留 |
| 跨库每边界崩溃 | SDK 提交前后、投影前后、水位写入、参与 store、清理前后逐点故障注入；重启幂等恢复 |
| 连续提交与日志留存 | B1 后 B2 更新/删除同对象再崩溃，按各批 image/tombstone 重放；未消费引用不被 GC；落后越界按固定切面 bootstrap 后追尾，不把 B2 当 B1 |
| 提交后取消 | 返回已提交/待恢复，不假称撤销；补偿操作另有 opId/expected heads |
| 页/块损坏 | 坏尺寸、整数溢出、截断、未知编码、解压超限、校验失败，失败不交半份可信数组 |
| SF3P partial | 父来源/布局/代次错配拒绝；已完成小窗仅在显式能力下预览；不以头完成当全部页已核验 |
| 取消与多消费者 | 单个视图取消不误停共享读取；最后 claim 释放资源；队列堵塞不能积压无界结果 |
| 旧库/未来格式 | 只读零写入；显式升级取消回滚；损坏元数据和未来 marker 不被空成功掩盖 |

失效后历史数值保留；currentness 与 reproducibility 分开：一个旧成果可以“与当前头不一致，
但旧输入仍可复现”。不得因为切当前主选而覆盖、删除或重算历史结果。

## 6. 性能验收方法

### 6.1 先证明工作量，再比较时间

| 场景 | 结构性验收，不依赖机器快慢 |
|---|---|
| 打开文档/来源第一页 | 不读曲线 BLOB、时深点、振幅；最多页面规定的 metadata/头部 |
| L0 SF3P 小窗 | 目录实际读量/驻留量随命中目录块增长，不分配 1.51 GiB 全 pageDir |
| 曲线 256 行晚页/窄窗 | 只解码命中数值块；原曲线从 1m 到 10m 样点后同范围读量不线性增长 |
| 层位深页 | 索引 seek，无全排序；VM/扫描行数与 page 大小相近，不与 offset 同阶 |
| 修改 W1 主选 | 不扫描全部版本和十类全对象、不清 W2 文件/页观测、不重建 SF3P |
| 一大多小导入 | active + done + sink + cache 的唯一内存分配受共同预算，超过则背压/spill |
| 一点编辑/小导入 | 写入和发布不随整个模型数据库大小增长；暂存、日志和旧代次容量可观测 |
| 多窗口共享读取 | 相同页/打开操作 single-flight；客户端 pin 与 LRU 逐出均入账 |

复杂度目标：有对应索引的 metadata seek 为 `O(log N + page)`；单调轴窗口为
`O(log chunks + selected chunks)`；增量同步处理 delta 条日志、相应索引查找及受影响
依赖边/下游节点，目标是不随无关全库线性增长，不能漏算索引 seek 和血缘闭包成本。
首次 bootstrap、正式解析、显式完整核验仍为线性工作，不能称为 O(1)。
范围索引、稀疏/非规则轴与支持域查询分别验收，不能用规则轴测试代替全部格式。

### 6.2 规模矩阵

- metadata：2k、100k、1m 对象与多版本，绑定/依赖按 1×/10×增长，包含重复名称和历史。
- 数值：1m、10m 样点，多曲线共享轴，稀疏/重复/非单调、缺值、raw/processed 差异。
- 地震：合成小体做逐值/缺测黄金比较；稀疏大文件或合成大目录做分配与范围验证；
  HY 做经授权的有限窗口和真实 shape 观察，不生成或完整转码百 GB 副本。
- 并发：1/2/4 消费者，重复/不同窗，慢磁盘、慢首 parser、慢 UI、取消风暴和磁盘满。
- 历史：pinned-value、follow-object-head、follow-selection 三种模式，长期 lease/WAL 压力、GC 和日志保留越界。

### 6.3 时延目标与证据标签

首轮候选目标：热 metadata 页 p95≤100 ms；热小窗 p95≤250 ms；普通设备上取消到安全
边界 p95≤250 ms；GUI 每次结果接管目标≤16 ms。它们均为待调校目标，不是已经达标。
冷的 SEG-Y 窗口、首索引、完整导入按字节/工作量给进度，不承诺固定毫秒值。

基准记录：提交、依赖版本、硬件/磁盘、数据 shape、查询范围、缓存模式、重复次数、
median/p95、实际源读量、解码量、输出量、RSS/预算高水位、复制与写放大。
进程首次打开不等于冷盘；若未清除 OS 缓存，标注 first-request/OS-cache-unknown。
不能用 3 个样本报告 p95。不同硬件的时延不直接比较，先看计数与增量比例。

## 7. 交付闸门

每批 PR 明确：完成的接口/消费者、仍走旧路径的范围、原件保护证据、schema/回退方式、
性能工作量与时延数据、故障注入结果。不能只附“全部测试绿”而不说明验证了哪些边界。

- 代码改造走最小链接集和相关 C++ 合约；Windows 串行，构建/测试最多 `-j8`。
- PR 前 fetch/rebase `origin/master` 后重跑 Source gates，基线不涨。
- 打包/部署改动检查 snapshot worker、Office 编辑组件及既有依赖闭包。
- 文档设计批次只做链接、事实/公式与源码闸门检查，不把旧 32 项回归结果说成新设计已实现。

首个代码实施 PR 建议限于 M0；把 1.51 GiB 目录分配、缓存身份与模型发布并发/恢复分别
做成可独立审查的小提交。更广泛的实体迁移在控制面协议稳定后推进。
