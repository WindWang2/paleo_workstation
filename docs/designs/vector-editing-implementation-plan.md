# 矢量编辑交互实施方案

基线为 `master@462592ca`（#1113）。第一批让用户能在交叉线上准确删除一条线，也能在按下 Ctrl+S 后看清哪些修改仍需提交。之后解决相面长笔画返工、工作副本切换和长时间编图中的撤销、参考与解释归属。

评估基线的普通点层画布实验中，点击两个重合点的中心选中 2 个要素，向左或右偏 3 个逻辑像素选中 0 个。在两个重合点中心或两条普通线的交点执行一次删除，两个要素都会消失，一次撤销均可恢复。这是首轮的复现夹具。现有相面分区继续使用专门的分割、覆盖和合并操作。

## 交付顺序

| 批次 | 可独立评审的交付 | 依赖 |
| --- | --- | --- |
| 第一批 | 1. 点选与单删。2. 保存状态与失败重试 | 两项可并行。分别通过主窗口的地图和保存入口验收 |
| 第二批 | 3. 继续编辑正确副本。4. 新相图的编图范围。5. 失败笔画就地修正 | 3 先确定工作副本身份。4、5 可分别开发，在同一张新相图上联验 |
| 第三批 | 6. 普通图层的跨层撤销。7. 参考区布局。8. 手动与后台解释归属 | 6 复用 2 的提交边界，8 复用 2、3 的版本与副本身份。7 可独立交付 |

每项建议作为一个工作分支和 PR。由 QGIS 封装负责几何、捕获、命中与原生编辑栈，工作流负责编图规则、版本和解释归属，视图只显示状态并发出用户意图。沿用当前地图、功能区、停靠面板、主题和键盘焦点规则。架构和视觉依据见[总体方案](../PALEO_QGIS_PLAN.md)、[分层约定](../UI_LAYER_PLAN.md)和[设计规范](../../DESIGN.md)。

## 第一批 · 防止误删和误判保存结果

### 1. 点选、单删与显式批删

普通矢量层中，鼠标悬停预高亮当前候选。点击唯一候选直接操作。重合时列出名称或标识，键盘上下切换预高亮，Enter 确定，Esc 取消。“删除所选 N 项”从显式选区执行。普通点击、Shift 加选、Ctrl 减选和拖框继续可用。

把点击与拖框按鼠标实际移动距离区分。点选、预高亮和单删复用同一套屏幕容差与空间命中规则，经图层 CRS 转换后检验真实几何。候选只取当前目标图层，按屏幕距离稳定排序。弹出列表后再校验工程会话、图层和要素身份。期间切层、结束编辑或要素已消失时取消本次操作。入口见[选择工具](../../src/ui/edittools/editingtoolbar.cpp)和[删除工具](../../src/ui/edittools/editingtools.cpp)。

**验收。** 以 512 × 512 画布上的重合点、十字线、共边普通面和单个独立点为夹具，记录地图比例尺及设备像素比。独立点偏 3 个逻辑像素可命中。交点单击并选择后仅删一条，另一条几何不变。取消后要素数与撤销栈不变。框选两项批删后一次撤销恢复两项。只读层仍可选择，相面工作副本仍禁止普通删除。测试从工具栏实际触发，并向画布发送鼠标事件。

### 2. 区分保存工程、提交图层和登记成果

Ctrl+S 保持保存工程。若几何编辑仍在缓冲中，显示“工程已保存，河道边界仍有修改”，列出涉及图层并提供“保存图层编辑”。画布和属性表读取同一编辑缓冲摘要，分别表达新增、删除、几何或属性变更。同一要素可能出现在多个类别中。对约束绘制显示其实际自动保存结果。

| 操作结果 | 界面反馈和下一步 |
| --- | --- |
| 图层提交失败 | 保留编辑缓冲、目标和具体错误，允许修正再提交。关闭或切工程时继续提供保存、放弃、取消 |
| 工作副本已落盘，版本登记失败 | 显示“工作副本已保存，成果版本未登记”，提供“重试登记”。重试前核对副本修订，若已编辑则显示当前待登记内容 |
| 成果版本已登记，后续井属性同步失败 | 显示已生成的版本号，提供“重试同步”。使用已登记版本的输入，成功后更新同步状态 |
| 多图层中途失败 | 分别列出已提交、失败、尚待提交的图层，下一次只处理未完成步骤 |

将图层提交、成果登记及后续同步的结果由工作流分别返回。沿用现有版本 ID、事件确认与暂存机制。校验连续点击重试、重开工程后重试、外部引用缺失及恢复。相同副本修订最多登记一个版本，每条编辑事件只归档一次。普通图层、属性表、工具栏和关闭工程这四条入口要得到相符的反馈。实现落点见[工程保存](../../src/ui/paleomainwindow.cpp)、[图层提交](../../src/qgis/qgiseditingservice.cpp)、[属性表](../../src/ui/attributetablepanel.cpp)与[相面版本登记](../../src/workflow/mappingworkbench_edit.cpp)。

## 第二批 · 避免选错副本和重画

### 3. 继续编辑时恢复明确的工作副本

“继续编辑”显示目标副本名，由工程会话、图层及工作副本 ID 定位。层位和分析单元用于筛选。候选只有一个时直接恢复，多个时供用户选择。打开参考图、对比其他版本或浏览属性表时保持编辑目标。请求新建副本前先处理旧会话，用户选择取消后仍停在原副本、工具和视口，工程中不会多出空副本。普通点、线、面图层的“添加”主按钮直接启动对应绘制工具。

以同层位两份副本加一份只读成果，测试新建、暂停、继续、切参考、取消切换和重开工程。对同一工程另用真实目录和目录链接重跑“生成图件→编辑副本→查版本”。对本地受管文件统一索引与查询的路径，保留图层来源中的 provider 参数及受管路径检查。入口见[任务向导](../../src/ui/pages/mappingtaskguide.cpp)、[副本命令](../../src/ui/workbench/mappingworkbenchcommandcontroller.cpp)、[版本索引](../../src/workflow/mappingworkbench.cpp)。

### 4. 把编图范围放在第一笔之前

新建空白相图时优先提供“使用已有工区边界”和“手绘范围”。显示图层、坐标系和边界预览，让用户明确选择初始微相后建立可细分的底面。手绘入口也可沿用第一笔兼作初始相面的操作，但须在落笔前说明后续图斑只在该范围内绘制。部分越界时预览裁掉的部分，完全越界时保留笔画待修正。

首笔保存前可整步撤销回空图。首次成功保存时，才沿用现有格式冻结覆盖范围。已有成果按原范围继续编辑。用含内洞的多部件工区、河道及邻接河漫滩验收，核对总覆盖、共享边、合法无数据区、已选微相，以及保存重开后的几何一致性。旧工程缺少独立范围文件时走原有读取路径。见[工作副本创建](../../src/workflow/mappingeditcontext.cpp)与[相面分区和冻结范围](../../src/qgis/faciespartitioneditor.cpp)。

### 5. 保留失败笔画，就地修正

画布现有提示行随手势显示已落顶点数、最近吸附目标和右键当前含义。分割线未切穿、自交等可修正错误保留本次顶点与目标，可移末点、退一点或继续加点。能定位的错误在地图上标出。用户按 Esc 明确取消。捕获期间切工程、目标被删除或编辑会话结束时废弃旧笔画。

在原生捕获结束前保留可恢复的曲线，先校验，再提交编辑命令。失败只更新预览，成功的一次撤销要同时恢复邻接几何、要素身份、来源和复核记录。验收用一条 20 顶点分割线故意让末点停在面内，只挪最后一点即可成功。失败前后历史长度相同，成功后增加一步。另测点数不足右键、Esc、自交、切副本、不同 CRS 与关闭工程。见[捕获回调](../../src/qgis/faciespartitiontool.cpp)与[画布提示](../../src/ui/paleomainwindow_docks.cpp)。

## 第三批 · 连续编图与解释复核

### 6. 一次跨层手势可整体撤销和重做

仅对显式开启跨层拓扑、同 CRS 的普通可写图层启用。节点移动、插入和删除在一个手势内登记全部参与层、各自原生栈起止位置和会话身份。写入前核对整组，任一层写入失败时回退本次已应用的部分。主窗口的撤销和重做先验证所有栈仍在预期位置，再整组执行。若其中一层已提交、销毁或插入其他命令，保持现场并说明涉及哪一层。会话结束时清理组记录。相面、约束及文本框保留各自撤销规则。

用两层共享节点从主画布按一次 Ctrl+Z、再重做，两层坐标须同步往返。增加一层写入失败、原生栈被单独撤销、跨 CRS 和焦点在说明输入框的用例。保留原生栈底层契约的既有测试。见[节点工具](../../src/ui/edittools/vertexeditortools.cpp)、[焦点路由](../../src/ui/edittools/undogrouprouter.cpp)、[编辑工具回归](../../tests/tst_edittools.cpp)。

### 7. 参考区把空间留给正在画的图

首次进入且所有参考为空时，用现有停靠面板显示紧凑的“添加参考”。选择资料后展开，初次默认两槽、单行横向排列，允许继续添加。已保存的显隐、浮动、宽度及用户已有布局优先。保留当前延迟创建参考画布、范围与光标联动、独立浏览。切工作页临时收起与用户主动关闭分别处理。选层和吸附／撤销配置始终可达。有可编辑目标时，在固定位置显示相应工具。没有目标时，按设计规范收起要素工具与编辑会话组。把现有“各组永远可见”的测试改为分别验证这两种状态和键盘可达性。

在 1440 × 960、窄窗口及 Windows 125%/150% 缩放下，记录空参考、两份参考和恢复自定义布局时的可绘面积。验证主图范围、工具、焦点和副本未被切走。反复切页、跨工程和重开都要恢复对应偏好。见[参考面板](../../src/ui/pages/mappingreferencepanel.cpp)、[停靠控制](../../src/ui/workbench/mappingreferencecontroller.cpp)与[功能区](../../src/ui/ribbonpanels.cpp)。

### 8. 解释明确到图斑、副本和版本

提供“给当前图斑加备注”和“后续编辑沿用这条说明”。前者绑定工作副本与图斑稳定 UID，后者绑定工作副本。未应用的输入按副本暂存，返回时恢复。分割、合并和撤销遵守既有来源与复核规则。后台结果回到原工程、原副本和原图斑，写入前核对几何指纹与相码。过期结果丢弃。草稿标注“AI 草稿”或“本地事实摘要”，显示所属对象和是否已随版本保存。

保存与绘制都可先于后台任务完成。晚到的草稿属于原工作副本。用户主动采用后可随下一版本登记。验收覆盖未配置模型、模拟成功、超时回退、手写时返回结果、撤销后返回、切工程、同层位两副本以及保存后返回。旧版本内容和已确认的人工说明不得被异步结果改写。见[解释表单](../../src/ui/pages/mappingeditbasis.cpp)、[解释归属](../../src/workflow/mappingeditcontext.cpp)与[异步保存测试](../../tests/tst_mapping_async_explanation.cpp)。

## 本地验证与交付记录

- **回归范围。** 第一批在 `tst_edittools`、`tst_attrpanel`、`tst_ui`、`tst_mappingworkbench` 中扩展正常入口用例。第二批加入 `tst_faciespartition`、`tst_mappingpages`，第三批按改动加入 `tst_mapping_async_explanation`、`tst_constraintediting`、`tst_draftautosave`。尽量在既有夹具中追加可重现的场景。
- **桌面走查。** 在 Windows 用鼠标、仅键盘分别完成“选交叉线→删一条→撤销→保存”和“选副本→画相面→修末点→登记→重开”。浅深主题都检查选中态、键盘焦点、读屏名称。另复测调整窗口尺寸后从固定微相切回自动显示的比例尺和相级。记录首次成功与否、误删数、需要重画的顶点数、切回正确副本的点击数。
- **大图性能。** 先建立 1 千、1 万、5 万图斑的基线。固定数据种子、顶点密度、一次笔画影响的图斑数、机器和依赖配置。每轮从同一底图起步，冷热分开。记录从右键到首帧更新、到下一次画布输入可响应的中位数和第 95 百分位，并拆分几何运算、校验和绘制。取得基线后再定目标。若瓶颈在全层合并或遍历，优先评估冻结边界缓存和空间索引。优化前后逐项核验覆盖、孔洞、稳定 UID、证据和撤销结果。[性能夹具与记录惯例](../perf/BENCHMARKS.md)
- **提交材料。** 每个实现 PR 写明所改入口、夹具、命令、依赖前缀、结果和未覆盖项。涉及界面的附改动前后截图及复现手势。基于最新主分支执行本地构建、受影响测试和源码门禁，构建与测试并行度不超过 8，传递分层检查显式传入项目 QGIS 头目录。执行方式见[仓库约定](../../AGENTS.md)和[构建指南](../../BUILDING.md)。
