# Windows 相面绘制响应基准

在同一个面内落四个顶点，右键完成编辑。按图层规模比较 1 千、1 万和 5 万个图斑，三种规模下的视口、落点和被修改的图斑数均相同。每个规模在优化前后各采集 20 笔冷态、20 笔热态，共计 240 笔。

## 环境与采样

- Windows 11，AMD Ryzen 7 7840HS，MSVC Release（`/O2`），工程依赖 QGIS 4.2.3、Qt 6.11.3、GDAL 3.13.3、GEOS 3.15.0。使用原生 Windows 窗口，桌面缩放为 100%。
- 每个规模使用固定 100 列、每格 10 × 10 米的内存图层和同一空间索引，每笔修改一个图斑。QGIS 单线程绘制，关闭画布渲染缓存。冷态是新图层的第一次覆盖编辑，热态是撤销回底图后的第二次覆盖编辑。
- 在构建与功能回归结束后分四批串行采样，每批每个规模运行 10 轮。依次测优化前、优化后、优化后、优化前。两版共用 `c090f8bf` 的测试对象、编译配置与依赖。优化前替换为 `a2f63a2c` 的 `faciespartitioneditor.cpp`，优化后使用含 `dabf84f8` 的编辑器。预跑数据单独保存。结果针对内存图层和固定视口。
- Windows 逐笔记录含批次、笔序和六种计时，可按规模和冷热态独立重算。[Windows 原始样本](baselines/facies_capture_windows_20261125.csv) · [复现命令](BENCHMARKS.md#相面覆盖绘制的交互延迟)
- 早期 Linux 开发样本使用旧计时夹具，个别 `render_ms` 会受下一帧开始信号影响。上表的 Windows 样本在首帧完成时锁定起止时间。[历史开发数据](baselines/facies_capture_20261125.json)
