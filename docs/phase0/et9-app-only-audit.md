# ET9 Audit — qgis_gui vs src/app capabilities at QGIS 4.2.x

Repo: /tmp/qgis-src — branch `release-4_2`, commit `53d73a8f` (2026-09-23).
Scale: src/app ≈ 333 headers / 334 cpp; src/gui ≈ 815 headers; src/core ≈ 1082 headers.

## Headline finding: src/app is now a shared library, but not a supported one

- `src/app/CMakeLists.txt:496` — `add_library(qgis_app ${LIBRARY_TYPE} ${QGIS_APP_SRCS})` → **libqgis_app** (SHARED by default per `CMakeLists.txt:187-191`).
- `src/app/CMakeLists.txt:644-648` — `GENERATE_EXPORT_HEADER(qgis_app BASE_NAME APP ...)` produces `qgis_app.h` defining **APP_EXPORT**; 178 app headers use it (`class APP_EXPORT QgisApp` at `src/app/qgisapp.h:229`, layout designer, vertex tool, etc.).
- `src/app/CMakeLists.txt:710-714` — libqgis_app is **installed** to `QGIS_LIB_DIR`.
- BUT: app headers are **not installed** (the `PUBLIC_HEADER` property is never populated; contrast `src/gui/CMakeLists.txt:2110` `install(FILES ${QGIS_GUI_HDRS} ...)`), there is no CMake export config for it, no Python/SIP module for app classes (sip covers core/gui/analysis/3d/server only — `python/PyQt6/*/…_auto.sip`), and some app classes lack APP_EXPORT entirely (e.g. `QgsGuiVectorLayerTools`, `src/app/qgsguivectorlayertools.h:26`).
- Conclusion: linking libqgis_app is *possible* (symbols exported on ELF, PUBLIC include dirs listed) but **unsupported and brittle** — treat src/app as non-exported app code for product planning; QgisApp singleton is `class APP_EXPORT QgisApp` but embedders must supply their own headers build anyway. `qgis_app` exists mainly so the `qgis` binary and unit tests share the app objects.

## Key takeaways for Paleo Workbench

1. **Biggest gap = layout designer chrome.** Everything needed to *build* a designer is in qgis_gui (view, tools, item widgets, `QgsLayoutDesignerInterface`), but `QgsLayoutDesignerDialog` itself is 5k lines of app code deeply wired to QgisApp (32 refs). Budget a real port or a thinner custom designer shell.
2. **Digitizing stack is nearly all GUI.** Cad dock, capture tools, digitize-feature, snapping utils, edit base — 0 QgisApp refs. Missing app pieces: concrete shape tools (thin port), vertex tool/editor (thin-medium), geometry-edit tools (thin each), snapping config widget (trivial).
3. **Vertex editor is surprisingly portable** — 0 QgisApp refs in the dock; the app-only LockedFeature/VertexTool pair is the real dependency (9 shim-able refs).
4. **Processing exec UI fully moved to qgis_gui** in 4.x (`QgsProcessingAlgorithmWidgetBase` is a *widget* you embed; batch dialog base too). Only glue is app.
5. **Locate/search**: widget + engine are gui/core; all 11 filters are small app files — cherry-pick the ones needed (goto, active-layer features, bookmarks likely; actions/settings/layouts less so).
6. **libqgis_app exists but is not a product surface** — installed .so with APP_EXPORT symbols (178 headers), yet no installed headers, no export config, no SIP bindings, and several classes unexported. Plan to vendor/port the needed app classes rather than link it.
7. Nice surprises vs QGIS 3.x memory: vector/raster/mesh/pointcloud **layer properties dialogs are now in qgis_gui**; annotation tooling in gui; devtools framework in gui; `QgsMapTip` in gui.
