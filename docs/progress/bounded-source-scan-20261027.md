# 新建工程的有界扫描（2026-10-27）

基线：`origin/master`，`1908a6c8`。分支 `codex/bounded-source-scan`，复用本任务
独立 worktree；原工区只读，私有文件、井名、坐标与截图不入库。

## 问题与原则

HXN 的识别阶段此前为了获取内部井名，完整解析 56 份曲线 XML 并丢弃曲线，
另对小于 200 MiB 的资料计算整文件 SHA-256。本机分段诊断约 83.65 秒，井名
解析占 72.89 秒，哈希占 10.58 秒；目录、分类与井表读取合计约 0.12 秒。

用户明确要求扫描不读取整个文件。本轮把新建工程的识别与正式导入分开：
扫描交付有界候选和预览样本，完整文件的一致性与数据体校验交给导入。

## 实现边界

- `sourceprobe` 以 16 KiB 分块读取文件前缀，取得内部井名候选即停止，单文件
  硬上限 256 KiB。支持原 LAS、带井名注记的文本、已有曲线 XML、综合 XML，
  以及 DLIS／LIS 的有界设备头读取。触达预算而无法取得身份时保持未决，不
  用文件名覆盖内部身份，不回退完整读取。完整解析 API 及单位口径保持不变。
- 新建工程不再计算资料或图件配套文件的整文件摘要。预览记录文件规范路径、
  大小、修改时间及已读前缀的指纹，创建／补充资料前复核这些信息；被排除的
  来源和未选图件不参与复核。这只绑定已读样本，不承诺未读尾部已被冻结。
- 井表文本读取至多 256 KiB，保留前 200 行。OOXML 预览只接受至多 2 MiB 的
  容器、4 MiB 的声明解压总量与 128 个条目，复用单元格规则并在每表 200 行
  后停止行解析；超预算工作簿保留来源、字段映射与源 CRS，等待正式导入。
  不再把通用完整工作簿读取器作为扫描回退。
- 点矢量使用有限要素预览。可能在打开时整读的 GeoJSON／JSON 超过 2 MiB
  则延迟完整读取；图件的大 JSON 只探测前缀，延迟 CRS 查验。
- 部分表格样本不用于推断整表重复，也不据不完整井名单产生错误的井名冲突。
  确认页与完成状态明确样本口径，完整数量以导入结果为准。
- 切换向导页时，若相同输入的扫描仍在途，复用该轮任务。来源变化时仍可
  启动新扫描；旧任务在块与文件边界检查取消，不再陷入整批曲线解析。

完整 XML 的不同井名、坏行、畸形尾部、采样深度与单位、坐标转换和源文件
SHA-256／复制期间完整性等仍由正式导入校验。有界识别不是“文件已完整验证”。
旧分井目录、集中组织与混合目录继续支持，固定辅助资料规则保持不变。

## 验证

本机 HXN 向导实测：两次识别为 **247／256 ms**，身份探测共读取 **1,191,872 字节**，
仍识别 57 份 XML（56 测井、1 份沿旧规则为辅助参考）、三个资料来源和
55 条数值井点预览。没有遍历约 2.33 GiB 的 XML 数据体。该计时为当前本机
一次扫描，不含进程启动、Qt／QGIS 初始化和正式导入。

新增回归检查真实设备读取字节数、提前停止与硬上限、块间取消、无重扫的
向导切页；覆盖 LAS／文本／新旧 XML／DLIS／裸 LIS／TIF 的内容身份提取。
还覆盖坏尾部扫描可保留候选但完整解析／导入拒绝、同大小同时间的前缀替换
被拒绝、CSV／XLSX 的 200 行样本与完整读取分离、部分样本不误去重、超预算
工作簿保留显式字段与 CRS，以及压缩与解压预算分离。
