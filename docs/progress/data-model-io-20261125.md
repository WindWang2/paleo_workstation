# 工区数据模型与 I/O 实施记录

本轮以两个独立工程交换数据为主线，涵盖原件、井筒身份和解释成果。系统对接采用本地文件包验证。字段对照、完整业务范围及后续批次见[实施方案](../architecture/DATA_MODEL_IO_IMPLEMENTATION_PLAN.md)和[117 行字段对照](../architecture/DATA_EXCHANGE_REFERENCE_20261125.csv)。

## 用户入口与数据归属

| 要做的事 | 入口 | 可持久回读的结果 |
|---|---|---|
| 收发 LAS、SGY、SEGY | 发送工程的“导出数据”选择原件和原生格式；接收工程在数据页选择“接收原件包”，也可将单个包目录拖到助手 | 发送工程 ID、资产版本、长度和完整 SHA-256。接收文件与 `receipt.json` 在接收工程 `artifacts/received/<收件ID>/`。收件按发送工程与版本幂等，旧包可由人工补充稳定来源标识 |
| 导入已收原件 | 收件完成后走正常文件导入入口。人工可确认类型和井归属，助手可处理确定项并提交待核对项 | 每次已执行导入的行级结果进现有台账；原件目录内独立的 `import-*.json` 记录本地解析结果及可确认的本地 RAW 版本。收件完成即可保留原件，解析与井筒确认各有自己的结果 |
| 查看和确认井筒 | LAS 资料预览、文档命令和助手井详情 | SDK 存储稳定井筒身份、来源成员和外部键；旧井可读为主井筒。确认基于实际模型代际、明确的井和当前来源。多来源／多井筒选择保留来源版本 |
| 交付分层与三维时间层位 | 从连井剖面导出分层表；从解释成果的“导出数据”选择交换格式；接收方用补充文件或助手导入 | 分层保留轴、深度单位和已有解释属性。独立三维层位用 inline/crossline、双程毫秒、置信度、调查及父版本描述格点。接收方显式绑定本地测区；缺少空间坐标时保留格点坐标 |
| 交付井的时深资料 | 在交换格式中选择已登记的单井 Petrel checkshots 来源版本 | 保留原表、来源工程和版本、完整摘要与已声明的时间和深度语义。重开后可读点列，转换使用文件声明的单位、单／双程和基准 |
| 取指定井筒的曲线 | 在井的曲线查询中选择井筒后按窗口取样 | 读数前核对井筒、井、来源文件、曲线身份和模型修订。同井不同井筒都含 GR 时可以独立取值，待核对的来源单独计数 |
| 创建工程与生成大文件 | 新建工程的默认目录为 `D:/PaleoProjects`；缓存、受管副本和操作暂存由数据层决定位置 | 新建工程核对真实目标卷，地震索引、转码及预览不依赖源目录可写。取消、空间不足和源数据离线各自上报 |
| 将旧工程迁到 D 盘 | 在工作台打开非 D 盘工程后只读预检，从工程菜单选择迁移位置 | 在 D 盘暂存并校验清单内成员、受管资料、工程数据库、导入历史及恢复日志；成功后再切换。共享目录中的无关文件留在原位置。可确定归属的图层路径随工程调整，需确认的外部来源列出原地址和版本，沿用资料重定位入口 |

## 功能与数据的边界

| 业务链 | 功能层职责 | 数据层职责 |
|---|---|---|
| 原件导入 | 排队、进度、取消、工程切换检查、旧包身份确认、收件后发起导入 | 流式摘要、原令牌复核、续传前缀校验、同卷就位及回执、结构化表读写 |
| 查询与井筒确认 | 文档命令核对用户选择及工程写权限，助手复用同一查询 | SDK 管对象身份和来源声明，工程资料树经查询服务读井和测区摘要 |
| 制图编辑 | 工作台决定是否登记版本、是否续做井属性同步 | 保存日志负责原子保存、恢复、预期令牌核对与清理；图层几何仍由 QGIS 处理 |
| 岩石物理 | 工作流编排跨井进度、取消与部分完成；切换工程后保留原位置的结果文件 | 数据服务固定单井输入、读曲线、调用算法、写成果；目录保存父版本和处理参数 |
| 导入历史 | 工作流在实际提交后组装行级结局 | 目录模块读写原有 `.paleo/import_ledger.json`，沿用旧版本格式；收件目录的字节回执独立保留 |

## 联调与扩展边界

本地交换格式在元数据中声明版本。外部平台的认证、接口地址、外部资源键的分配方、字典和字段必填规则，需以对端给出的协议和样包验证。LAS、SEG-Y 已有独立的原件通道；样品、照片、断层面、相带多部件几何等其他资料族按各自的业务对象和版本扩展。旧数据中缺少的单位、基准、井筒身份或调查绑定保留为待核对。

现有工程继续通过 `project.paleo`、工程目录库和 SDK 打开。此次兼容核对按具体业务入口进行；多井筒身份、完整的历史数值重放与各专业算法按井筒筛选是不同能力，应分别验收。

| 方案批次 | 本轮可核对的范围 | 余项 |
|---|---|---|
| 0–1 基线、位置和原件 | 两工程往返、D 盘位置约束、旧工程只读和副本迁移、复用旧快速指纹 | 真实超大体的完整复制压力测量，以及用户待迁移工程的逐工程核对 |
| 2–3 身份与井资料 | 井筒和来源成员身份、显式确认、按井筒读取曲线窗口、分层表和单井时深交换、岩石物理编排 | 多井筒轨迹、样品／测量及专业计算的逐消费者切换，更多类型的历史数值回放 |
| 4 地震、GIS 和制图 | 工程内地震缓存与索引、窗口回读、独立三维时间层位交换、编辑保存与恢复日志 | 二维解释、深度域层位、断层棒／面及相带几何的正式对端交换 |
| 5 外部对接 | 离线文件包、稳定来源、完整校验，以及本地收件、解析和身份确认 | 对方系统的接口、认证、字典、对象／资源键及双向冲突联调 |

## Windows 验证

测试使用仓管 QGIS、Qt、GDAL、地震引擎和 Office 组件。测试工程及 `TEMP`、`TMP` 位于 `D:/PaleoWorkstation-validation/data-model-io-20261125/tmp`。实数用例通过 `PALEO_HY_SOURCE_ROOT` 只读访问 `D:/HY测试数据`。构建最多 8 路，测试逐项运行。

- 两个 D 盘隔离工程通过工区目录导入、原生导出、接收、再导入和 SDK 重开，小型 LAS 和 SGY 的两端字节相同。另测补充文件入口、相同收件复用、传输内容冲突、取消、已有部分数据恢复及旧包发送方标识。直接收件与工程关联分别断言。
- 真实工区清点 2,051 个文件、381,389,185,015 字节。Windows 实数套件 8 项通过，未跳过。测试前后比较每个源文件的大小与修改时间。9 口井有多份时深来源；选井后回读 870 个曲线样点与地震小窗。分页文件头读取 8,256 字节，独立 SEG-Y 核验读取 65,536 字节。大体全量传输的吞吐、峰值内存及断点恢复时间另行实测。
- 用工作树的 QGIS 头目录执行 `python tools/check_layering.py --transitive --strict --qgis-include "$env:QGIS_PREFIX/include"`。岩石物理的统计值移入领域类型后，重头依赖边由 48 减至 47，受影响的编译单元由 41 减至 40；基线同步下调。

**最终结果。** Windows 原生 `paleo.exe` 构建成功，42 个受影响的测试套件按最终核验结果全部通过。QtTest 文本共记录 568 项通过（含初始化和收尾）、0 失败、19 项跳过。跳过项包括按需截图、指定外部样本或压力基准、权限无法复现的旧台账用例。HY 文件窗口和上述数据交换用例均已实际运行。44 项源码检查通过；冻结后的翻译检查为中英各 11,884 条、无缺项。参考 CSV 已核对 115 条有原编号、2 条无原编号，两个文档的本地链接均可解析。

| 重点回归 | 实际观察 |
|---|---|
| `tst_originalpackage`、`tst_agentattachmentimport`、`tst_dataexport` | 两工程之间整件校验，已收原件先返回回执、解析后再登记版本；中断、重复和同版本冲突各自覆盖 |
| `tst_dataservice_wellbores`、`tst_document_relation_session`、`tst_wellbore_curve_window`、`tst_pythonanalysiswiring` | 同一口井的 GR 在主井筒取到 10、20，侧钻取到 110、120；指定错误井筒时采样读取为 0 字节，过期目录映射不能启动任务或登记成果 |
| `tst_sectiontopsexchange`、`tst_horizonexchange` | 从所选历史版本往返时深表，核对分层属性、时间层位逐点数值以及转发后的原发布身份 |
| `tst_projectfile_safety`、`tst_projectsetup`、`tst_shell_projectlifecycle`、`tst_releasepanel` | D 盘独立子目录建工程并重开成功。有效 LAS 与错误井口坐标可以同批预览。打开旧工程、关闭和切换至 D 盘副本后，旧目录没有新增文件，已有发布库字节一致 |
| `tst_petrophysbatch`、`tst_welllog_consumers`、`tst_p6_mapsave`、`tst_io_importledger` | 跨工程不得错登计算成果，旧测井消费方、编辑保存恢复和已有台账兼容性均通过 |
