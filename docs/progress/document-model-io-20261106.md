# 文档模型、窗口读取与发布恢复：第一批代码实施

本记录接续 [M0–M5 目标设计](../architecture/MODEL_MIGRATION_AND_VALIDATION.md)和
[A0–A4 能力设计](../architecture/ATOMIC_CAPABILITIES_AND_AGENT.md)。这是分阶段接入，
不代表所有旧入口、历史数值版本、精确失效或 Agent 操作持久化已经完成。

## 已接入的路径

| 范围 | 当前实现 |
|---|---|
| SF3P | v6/v7 页目录与完成位图按需读取，64 KiB 块共用有界 LRU，默认 4 MiB；打开不预载整个目录。SDK 独立构建的 vendored 引擎同步同一补丁。 |
| 曲线 | 新导入同事务建立共享轴与独立数值小块，每块最多 4096 样点；深度窗、索引窗与旧曲线分页使用同一读口，保留 raw/processed/quality、辅助轴、未知声明及 float64。 |
| 旧业务读口 | 连井输入捕获只读取选定曲线和辅助轴；井特征表与地震分层曲线窗传递累计预算和取消，不再先读取整组曲线。 |
| 模型日志 | SDK 事务提交业务值、薄元数据 after-image 和批次 receipt；storeId/generation/sequence 定义增量范围，删除有 tombstone，跨页固定同一 batch。 |
| Catalog 投影 | 首次或换代 bootstrap；后续消费完整持久批次，事实与 checkpoint 同一个 Catalog 事务提交，无变化时不扫描十类对象或所有版本。 |
| 模型发布 | 导入准备期固定 active head，发布持 active/暂存双写 gate 并核对 CAS；持久 intent 覆盖目录切换和投影恢复，重开工程重试，不重新解析原件。 |
| 算法输出 | 必需端口、文件指纹、输入版本及目标 head 统一校验；多个成员和完整 manifest 同事务登记。兄弟依赖必须无环，按拓扑顺序建立证据和版本。 |
| 实际多输出消费者 | 草稿相图 GPKG 与 QA JSON 成组发布；异步任务在 worker 写文件和校验，owner 只登记及声明图层。准备失败不能在 owner 重试写盘。 |
| 共用能力入口 | `catalog.version.describe.v1` 采用明确 documentId、versionId 和目录修订，提供统一请求/结果 schema；聊天 `query_project(topic=version)` 调用同一类型化入口，批处理和其他宿主可直接调用。 |

来源投影保留同井多来源。按稳定来源 ID 对账，不把相同内容的新来源改写成旧来源；
bootstrap 也核对停用、失败、忽略、删除、位置变化和 RAW/DERIVED 区别。缺失角色及
退休来源的旧关联进入待复核，历史版本不删除。分层/时深的实际对象和用途绑定沿用
已有文档会话契约；本批没有将多个体系折叠成一条井级字段。

## 预算及兼容边界

- SF3P 每次请求最多交付 64M float、规划 1M 页，单页解码最多 64 MiB；目录读取及
  buffer 驻留单独计数，payload 仍沿用原 readBytes 口径。它们不是进程 RSS 或全局预算。
- 曲线读取分别限制交付样点、累计 BLOB 载荷字节与取消；声明字段有固定元数据上限。
  min/max 块索引允许乱序、重复、缺失深度，候选块仍逐点过滤。坏块会撤销 ready 状态。
- 曲线计数是 SQL 交付的数值载荷，不是物理磁盘读量。非单调轴可能命中多个块，
  不承诺任意轴上的常数成本。旧大 BLOB 不用 SQL substr 冒充真实增量读取。
- 旧库只读打开不升级。小旧载荷只在默认 1 MiB 兼容预算内物化；更大者明确要求
  显式迁移。当前迁移默认累计 64 MiB，事务失败或取消整体回滚。
- 日志单卡片最多 8 MiB、batch 最多 64 MiB；读取页最多 16 MiB。Catalog 先接完整
  batch 再原子应用，不把半页当已同步。来源卡片只含对象目录，不含振幅、曲线或时深点。
- 外部 SQL 绕过 SDK 上下文会触发 unmanaged，日志拒绝宣称连续历史；明确可写重开后
  换 generation 并重建投影。写 gate 只能协调已接入的 writer，不能替未适配写口承诺原子性。
- SDK 可写连接显式采用 `synchronous=FULL`。每外层写入检查 active 文件物理身份和
  store/generation，旧连接不能在目录切换后悄悄写入 retained 旧库；当前实例自己 fork 后
  可以继续写。普通重开及被忽略的元数据插入不应伪造新代次或批次。
- Catalog 投影索引首次建立及无关 Catalog 改动后的失效重建仍可能遍历目录；首次
  bootstrap 仍读取全量薄元数据。本批未完成 M5 的全部有界目录与依赖索引。

## 恢复与保留

旧模型目录保留为带 receipt 的 previous 代次。当前缺少所有 legacy reader 的持久租约
登记，因此不自动递归删除旧模型；后续需有容量统计及显式、可证明安全的 GC。
数据库快照没有带齐仍在线的受管原件时，发布明确拒绝，保留当前模型。当前工区外部
引用导入不复制大型原件；受管原件的有界搬迁/重用仍需后续实现。

相图和报告登记成功后，图层声明可能单独失败：成果版本仍保留，不删除已登记文件。
统一的“已提交、待呈现”恢复回执尚未全面接入，不能将这种情况描述为完全无副作用。

## 验证口径

新增合成合约覆盖：大稀疏目录与宽时间面读量、partial 完成位、缓存代次隔离、曲线
晚页/乱序重复深度/辅助轴精度、坏块/预算/取消/编辑回滚、旧库升级、日志 after-image
与事务故障、未来版本竞争、发布各目录边界恢复/CAS、checkpoint 故障回滚及重开、
多端口缺失/依赖环/SQL 失败整组回滚，以及后台准备失败不能转到 owner 重发。

实数据只做只读检查及临时工程导入，核对原目录文件清单、大小和修改时间；不生成完整
地震副本，不转码百 GB 原件。本次 HY 只读回归覆盖两份时深来源、9 口同井多来源、
按用途隔离实际关系、工作表/文件名身份冲突、私有副本重定位、complete/partial。
真实 SF3P 的 1×1×1 请求读头 4,112 B、目录及位图 131,072 B、payload 19 B，目录
buffer 驻留/峰值均 131,072 B；真实 LAS 单样点读 SQL 载荷 102,400 B，各命中一个轴块
和数值块，不物化旧 BLOB。这是有限请求的工作量证据，不是全体文件完整性验证或 p95。

Windows/MSVC 本地完成 27 项相关工作站回归（含应用装配/聊天入口和 HY）、9 项独立 SDK
合约；SDK 安装后的独立消费工程完成配置、编译、链接和模型 API 调用。完整应用装配静态库
已构建，Office 编辑组件配置就绪。源目录 2,051 个文件共 381,389,185,015 B，验证前后的
清单、大小与修改时间一致，私有 LAS 副本重定位还核对了原件内容摘要。
28 项 Source gates 在 fetch/rebase 后通过，未增加任何基线。远端 Linux/Windows 全量 CI
另由 PR 验证；本机没有执行 POSIX 条件分支。
