# 文档数据 Swarm 修复（2026-11-05）

接续文档来源第一批，在 PR #904 与配套 Data_service PR #12 上修复审查发现的
13 项问题。来源关联、井/分层查询、地震与性能由三个子代理并行修改，主代理负责
原生模型快照、跨库编排、宿主消费、交叉复查及统一构建验证。没有合并到 master。

本页记录第一轮修复；后续类型化关系、对象修订、精确失效与可取消快照的当前实现见
[第二阶段记录](document-contexts-20261105.md)，下文的未闭环项与快照取消限制按阶段读取。

## 状态与性能边界

文件换位置仍保留 SourceRef。原生模型的新快照使用 `storeIdentity` 保留逻辑模型身份，
物理 `path` 与 `sha256` 指向新快照。旧模型与原文件不改。两个库没有跨库原子事务；
操作意图承接模型已提交、Catalog 未提交或仅日志清理失败的恢复。
同内容定位更新保留整个派生链；若重发布历史 RAW 越过了不同内容或解释的 RAW，
则作为当前输入的实际回退执行既有失效规则，不能一概豁免该资产的所有下游。

SEG-Y quick 核验仍最多读取 64 KiB，不升级为数百 GB 文件的全量哈希；SF3P 来源检查
只读有界头部，未完成分页不视为可用，且不声称验证了全部振幅页。原生模型创建快照
发生在后台；SQLite `VACUUM INTO` 执行期间暂不能协作取消，前后和哈希阶段可取消。
大型原生模型仍存在快照时间与磁盘成本，本批没有宣称其为常数成本。

普通同井、相同已知 MD 轴/单位且双方起算面均未填的直接曲线切片保留兼容；
不据此允许时深转换。跨轴、跨单位、起算面冲突或仅单方已知时保持未解决。

## 尚未闭环的通用模型

本次没有实现完整的类型化 InterpretationContext / RelationUseSpec 解析器；
SourceBinding.scope 仍是不透明字符串。多业务视图仍需逐批改读会话；时深/分层语义修订
到全部派生成果的精确依赖失效、跨体系映射及显式分段关系仍按第一批文档继续推进。
地震框架全工区层位采集的目标体、来源冲突和修订归属也需要后续独立建模。
