绿色结论的可信度被两套「放行」机制稀释——它们的**约束机制都已实现，但都没接线**。

## 证据

### 1）失败项串行直跑通过即放行（无台账）

- `tools/ci_ctest_gate.sh`：并行轮失败后，非崩溃类失败串行重跑一次，「重跑通过仍留痕」，仅 `::warning::`。
- `paleo-dev.ps1:395-430`（Windows 侧同路径）：env_redset 分类后，未豁免项直跑一次，通过即放行。
- 实证 run 38835970978（linux 车道）：373 项 2 红（`tst_wellsiting_kernel`、`tst_evidencee2e`）→ 串行重跑通过 → job 判 `success`。
- **无 flaky 台账**：同一测试反复靠重跑放行不会被累计、不会被升级为硬红。

### 2）环境债名单的「只减不增」机制已实现但未接线

- `tools/env_redset.json` + `tools/check_env_redset.py` 已实现 `STALE` 分类：exempt 项本轮通过 → 名单可删此条，`--strict` 下按失败算（防名单僵化）。
- 但 CI 侧调用**不传 `--strict`**（`paleo-dev.ps1:408-409`、`ci.yml` 对应 steps）→ `STALE` 从不触发，名单事实上**只增不减**。
- 与 #474（`--symbol-audit` / `--transitive` 有工具未接线）同族：**有约束、无强制**。

## 影响

- 超时类失败可能掩盖真实性能退化（TODOS.md 已记 golden 17/48 超容差、`tst_cache_las`、`tst_perf_catalog`、`tst_singlefactor_perf` 等文档化红项，同族）。
- 偶发竞态被吞掉后，直到用户机器上复现才被发现；名单无限增长会让豁免面持续扩大而无人复审。

## 建议

- **接线 STALE**：CI 侧给 `check_env_redset.py` 接 `--strict`（或先接「STALE 只提示不红」的过渡档），并给名单条目加 `reviewed_utc` 字段与季度复审。
- **flaky 台账**：直跑放行时写入固定台账（仓库内文件或 `flaky` 标签 issue），按周复审；同一测试命中 N 次即升级为硬红。
- 把串行直跑的放行 warning 提升为 PR 评审面可见的 annotation。

## 验证

连续两轮 CI 出现「出名单」或「台账新增」记录。

# 503 [med] 测试侧膨胀与反馈周期：Windows 全量 ctest 44 分钟、tst_panels 5,337 行

> **2026-10-16 复核修正**（两条）：① 原建议第 1 条「按 label 分片**并行车道**」经核对 `.github/workflows/ci.yml` 后需要加前提——windows 是**单个 job**（vendor 缓存 → build → selfcheck → test），分片意味着每个 job 都要**完整构建一次**（构建产物不跨 job 共享），runner 成本翻倍、总时长只省下约一半测试时间。**只有先把构建成本降下来**（ccache/sccache 对 MSVC、或把 vendor+build 产物做成可复用 artifact）分片才划算；在此之前优先级应放在第 3 条（定位 18× 差距）与拆巨型测试文件上。② linux 车道**已经是两段式**（`tools/ci_ctest_gate.sh -LE 'core|perf'` 再 `-L core -LE perf`，隔离模块标签优先后全栈伞式），并非未分片状态。

## 2026-10-16 二次复核：18× 差距的构成已定位

**结论：18× ≈ 并行度 8× × 单测试慢 2.2×**，原描述「Windows 慢约 18×（MSVC 链接/运行 + QGIS 装载/文件系统）」不准确。

| 平台 | ctest 并行度 | 报告的墙钟 | 等效单进程墙钟 |
|---|---|---|---|
| linux | `paleo-dev:104-112` 默认 `-j min(核数,8)` | 147.62 s | ≈ 147.62 × 8 ≈ **1181 s** |
| windows | `paleo-dev.ps1:388` **未传 `-j` → ctest 串行** | 2635.06 s | **2635 s** |

- **约 8× 来自并行度**（单进程等效 1181 s vs 2635 s 之间还剩 2.2×）
- **约 2.2× 来自单测试本身**（DLL 加载 / GDAL+QGIS 初始化 / 文件系统 / 沙箱 TEMP 重定向）

### 可行动项（需 CI 验证，未在本批引入）

Windows 保持串行的原文理由是「QSettings NativeFormat 走注册表，不受 env 控制」（ci.yml windows Test 步注释）。但**方向 81 已落地测试私有注册表 hive**（`tests/support/paleo_test_registry_sandbox.cpp`），该理由**可能已失效**——那条注释疑为方向 81 之后未同步更新。

建议单独 PR 试跑 `ctest -j4`：本机 worktree 只有 2 个测试目标，**无法本地验证并行安全性**，故不宜与本批修复混在一起提交。若并行可行，Windows 墙钟可直接从 ~44 min 压到 ~11 min（8× 的主要来源），这是本 issue 性价比最高的一项。

### 关于原建议第 2 条（拆巨型测试文件）

补充：拆分**不减少总墙钟**（用例数不变），收益在①失败定位粒度 ②本地可按族跑子集（如只跑 `dataPage_*` 20 个用例而非 144 个）。`tst_panels.cpp` 结构适合拆——单类 144 用例、命名已按页面分族（`dataPage_*` / `predictPage_*` / `constraintPage_*` / `composePage_*` / `validatePage_*` / `folderConfirm_*` / `mainWindow_*`），但需先把共享 Fixture 抽到 `tests/support/`，属独立工程。
