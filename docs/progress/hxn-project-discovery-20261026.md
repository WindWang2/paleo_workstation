# 新建工程识别集中组织的测井资料（2026-10-26）

基线：`origin/master`，`46f9fffa`（已包含 #788 的综合 XML 文件读取适配）。
本轮在 `codex/hxn-project-discovery` 修复新建工程入口，保留原有分井模式。
原工区文件、坐标与含私有井名的报告不入库。

## 原因与改动

此前总目录发现只匹配「井坐标／井位／wellhead」表和「井／井数据／wells」
目录。集中组织使用「坐标统计.xlsx＋测井数据＋参考资料」，前两项未被发现，
导致井点页字段、预览及测井来源为空；文件解析器支持 XML 并不能接通这个入口。

- 保留原有井位表命名优先级，新增坐标统计／坐标表／coordinates 的表格候选。
- 新增测井数据／测井资料／well_logs 目录；多种井目录共存、或总目录直接有
  XML／LAS／DLIS／LIS 时，沿用递归扫描与规范路径去重，保留两种组织的文件。
- 总目录发现只检查名称与文件类型；工作簿和 XML 内容仍由功能层启动后台扫描，
  不把大文件读取放入视图线程。
- 新建工程第一步说明两种组织，第二步自动展示坐标表、字段和预览，第三步自动
  填写测井与参考目录。未发现资料时明确提示，不再显示「识别完成」。
- 沿用原生四步表单与主题，没有新增配色、字体或视觉控件体系。翻译同步更新。

EPSG:2436 仍由资料设置明确声明，不变成所有工程的默认值；测量横纵语义与
用户显式字段映射保持既有优先级。带号、混合轴序和缺失数据仍需核实，本轮不
修改原始坐标、不猜转换规则。资料组织识别成功不代表坐标已通过入图校验。

## 验证

`tst_projectsetup` 新增从总目录出发的回归：

- 集中组织自动发现三个来源，并识别测量横纵字段。
- 原分井组织继续识别；新旧目录混用、根目录直接存放 XML 时不丢测井文件，
  重叠扫描不重复导入坐标表，旧命名优先级不变。
- 实际向导自动填入来源、字段和两行预览，明确输入 EPSG:2436 后创建工程、
  关闭重开，并通过统一曲线查询读取两口井的 MD／米采样与原曲线值。
- 空目录显示未找到资料；合成数据截图检查第一、二、三步，无私有数据外传。
- `PALEO_HXN_DATA_DIR` 显式启用本机 HXN 总目录只读验收，CI 不依赖仓外数据。
