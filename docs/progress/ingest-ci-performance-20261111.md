# 小文件入库与两项性能失败（2026-11-11）

## 入库：先区分波动，再缩短实际写库路径

上批每版本三次的小文件/10 MB 结果出现回退。本次在无本机编译或其他性能
测试并发的窗口中，比较最初 f40d5f82、当前 master 固定的 d25eb0e 和候选
5da59402。每场景使用六种 ABC 排列各一次，每版本六次、总计 72 次；每次
创建新数据库，使用相同 MSVC Release、Qt 6.11.2、copySources=false。

| 场景 | 最初基线 ms | 当前 master ms（范围） | 候选 ms（范围） | 相对 master |
|---|---:|---:|---:|---:|
| 0.49 MB XML | 730 | 740（657–827） | 238（218–292） | 快 67.8% |
| 10 MB XML | 1014.5 | 909.5（822–993） | 790（687–1200） | 快 13.1% |
| 33 MB XML | 3162 | 2674（2605–3441） | 2161.5（1988–3510） | 快 19.2% |
| 三文件目录，43.68 MB | 3671 | 3173（3066–3319） | 2376（2310–2604） | 快 25.1% |

中位数不是逐次保证；10 MB 候选有一次解析抖动，未删除该样本。旧版小文件
两个区间几乎重合，10 MB 的解析优化在复测中更快，故不能把上批回退认定为
稳定的 parser 回归。能确定的瓶颈是小文件大量原文单元格/层段的写入。

QSQLite 的 execBatch 实际逐行执行。改用参数化多行 VALUES，每批最多 256 行、
900 个绑定参数；整批复用 SQL，尾批重新准备。仍执行逐行约束/触发器、
每文件事务、FULL 同步、模型变更日志和取消回滚。小文件写库中位数
691→190 ms，10 MB 为 341.5→230.5 ms，33 MB 为 1225→573 ms。

单文件直接读取挂载 D 盘原件；目录测试读取其 C 盘字节一致副本、两个解析线程。
计时包含完整 DataService import 和数据库提交，不包含宿主快照/发布/目录投影。
没有清空操作系统缓存。72 次模型计数、SQL 行数及包含深度/曲线 BLOB 的语义
校验全部一致；重复导入和取消不改变结果，原件 SHA、大小、修改时间未变。

依赖改动单独提交 [Data_service #17](https://github.com/changyanyanchang/Data_service/pull/17)，
基于当前宿主已钉住的 PR16 分支，避免切回缺少模型日志/窗口 API 的上游 main。
没有提交私有资料、数据库或本地测量产物。

## 两项 CI 失败的实际复现

旧 CI 缺少 QtTest 详细输出。本批先只增加构建壳，不改测试或业务代码，在
Ubuntu 26.04、GCC 15.2、Qt 6.10.2 上重新运行原 c11ae3d3 源码。
[基线 run 43022735620](https://github.com/WindWang2/paleo_workstation/actions/runs/43022735620)
分别复现了两个失败，均已到达测试断言：

- geostat：LOO 交叉验证 2000 井 251 ms、8000 井 1585 ms，比例 6.31474，
  超过原门槛 6；克里金/SGS 和数值断言通过。邻域索引在每个 LOO 预测中重建
  数千个独立桶容器，去重还重复生成有限样本副本和中间映射数组。
- welllogset：冷 100 井 301.062 ms，随后已热的 10 井 1.100 ms，比例
  273.785，超过门槛 20。比较的缓存状态不同，无法表达规模线性度。

geostat 将桶改为计数/前缀偏移/连续索引数组，保留原桶访问顺序及桶内点序；
去重直接排序原始索引，保留重合点累加、映射和非有限值语义。原墙钟比例门
24/6/6 保留，另记录线程 CPU 时间帮助区分计算与调度，不以 CPU 指标替代墙钟门。

welllogset 分开比较互不重叠的冷集合，再测热/热比例，保留 500 ms 与 20 倍
门槛。生产路径复用一次格式嗅探并缓存格式与表头，LAS 字段正则按线程复用。
缓存额外核对高精度文件变更时间：Windows 用 FILE_BASIC_INFO.ChangeTime，
Unix 用 stat 纳秒值；取不到可靠标记时不复用缓存。同长度修改并恢复 mtime
仍须刷新，不能以去掉校验换速度。原生模型优先级和 XML/文本完整验证均保留。

新的 native-perf 车道直接编译相同生产源文件和测试，两个任务分开运行，
不依赖 QGIS 下载完成；同时覆盖邻域/求解器数值回归、测井格式回归和五项
Data_service 契约。它补充完整应用 CI，不替代 QGIS 集成或交付验证。
