# 文件入库性能复核（2026-11-11）

本批保留每文件事务、SQLite FULL 同步、完整来源哈希、原始曲线及窗口块、
修改记录和发布租约，不以降低持久性换取速度。数据层负责解析与存储，
功能层在整批资料读入后安排一次派生模型生成，视图层没有新增数据处理。

## 改动

- SpreadsheetML 标签使用 `QStringView` 比较；工作表井号和连续相同原始井号的
  规范化结果复用。仍逐行检查井归属冲突，保留原文和 GB2312/CP936 流式解码。
- 新建/补充工区的多个输入先完成导入，再统一继承约定和生成一次地层框架。
  全部失败或输入目录全部消失时不生成新修订；取消后不发布暂存模型。
  独立单文件/目录入口仍立即生成，显式重建仍保留历史修订。
- 井登记比较原始存储记录，仅持久化变化字段。不能用已经叠加工区模型的公开读口
  做比较，否则会掩盖尚未落盘的变化。重复登记不增加 catalog mutation sequence。
- 入库入口拆到 `areamodel_import.cpp`，并单独记录派生模型生成耗时；原
  `ImportReport` 的 parse/store/elapsed 不包含宿主快照、发布和目录投影。

## 真实文件 A/B

基线 Data_service `f40d5f82`，候选为本批最小解析改动；同一 native MSVC Release、
Qt 6.11.2、`copySources=false`。每次创建新的目标数据库，单文件直接读取已挂载
D 盘的原件。按 A/B/B/A/B/A 顺序，每版本每场景三次，下面是完整 import 调用
（含解析和事务提交）的中位数，不含创建工程、结果校验和应用层发布。

| 场景 | 基线 ms（范围） | 候选 ms（范围） | 中位数变化 |
|---|---:|---:|---:|
| 0.49 MB XML，分层为主 | 905（797–987） | 1012（965–1116） | 慢 11.8% |
| 10 MB XML | 1103（1079–1255） | 1174（929–1248） | 慢 6.4% |
| 33 MB XML | 4363（3765–4670） | 3607（3339–4623） | 快 17.3% |
| 三文件目录，43.68 MB | 5857（4743–6807） | 4833（4637–4988） | 快 17.5% |

目录批量使用上述 D 盘原件的字节一致 C 盘副本，两个解析线程，读盘位置和单文件
测试不同。33 MB 的解析中位数为 2606→1907 ms，写库为 1631→1653 ms。
当前证据支持该大文件和该批量场景的改善，不能声称小文件或写库普遍提速。
运行未清空操作系统文件缓存；区间存在波动，三次测量不构成统计显著性结论。

24 次导入的公开模型计数、SQL 表行数及全字段语义校验一致，校验覆盖深度、
原始/处理后曲线、质量标记和窗口 BLOB。三文件共三井、15 曲线、379120 个曲线
样点、16 个分层道、1903 个层段。重复导入和取消后这些结果保持不变；原件的
SHA256、长度和修改时间未变。数据自带的 review 状态照实保留，没有忽略问题。
