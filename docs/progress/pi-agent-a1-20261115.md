## 范围与用户链路

用户通过独立锁版供货准备可选 Pi 组件，显式安装后提供 root 与独立批准的 manifest SHA；C++ 完整核验供货、source lock 与文件集合后才取得 opaque runtime，并通过固定 hello/close 协议完成最小握手。默认构建、安装、应用启动均不要求 Node，安装不会自动启用 Pi。

A1 不连接模型、项目工具或 conversation，也不开放任意 JavaScript。Pi 是宿主信任的编排组件，`isSandbox=false`；不能把 Node 进程当成 Python 强隔离后端，亦不提供 OS CPU／内存硬限额承诺。可信供货与业务执行准入是两条不同边界。契约依据为本批 `vendor/pi/README.md` 与既有 A1 progress。

本次继承 E2 的宿主准入／绑定与双语文案修正，原完整构建与本轮单测试增量的源身份分别见下表。A1 原供货、独立批准 SHA、握手和默认不启用边界不扩大；后续业务能力依次由 A2、I1/I2、O1/O2 承接。
