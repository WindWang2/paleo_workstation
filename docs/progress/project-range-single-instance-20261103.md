# 工区范围图层重复修复（2026-11-03）

用户 tt3 保存工程中，同一 `ast-1952/ver-1956/project_range.gpkg|layername=area`
被恢复为六个地图图层；目录中只有一份范围资产和一个版本。不是 DataService
重复计算范围，也不是历史版本重复登记。

范围 QML 在 `paleoLayerId` 写入之后加载，会替换自定义属性，导致保存重开后
服务认不出已恢复的范围实例，下一次请求再次添加。注册期间的同步回调也可能
在缓存登记前重入实例化。

修复将稳定标识写入放在全部样式加载之后、项目注册信号之前，并提前建立实例
缓存。打开工程及请求当前范围时，按声明的 OGR 完整来源（规范路径及表/筛选
等 URI 参数）收编缺失标识的实例；同一范围保留一个当前有效实例，合并勾选态。
明确标为其他用途的图层、不同来源和编辑缓冲均保留；新来源不可读时不清除最后
可用实例。移除仅作用于地图注册表，不删除范围文件、原始资料或目录版本。

验证：`tst_projectboundarylayer` 六项固定测试（含 init/cleanup）通过；实际 tt3
只读打开验收加一项，总计 7 passed。原工程六个范围收敛为一个，其余 29 个
图层身份不变，修复结果仅写临时目录，重开后仍为一个。固定测试覆盖样式身份、
反复切层、保存重开、旧副本去重、手动图层/文件保留、勾选态、编辑态保留、无效
替换和注册同步重入。图层平台回归 `tst_layerplatform` 20 passed。
