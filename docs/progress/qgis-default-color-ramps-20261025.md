# 属性窗口恢复 QGIS 默认色带

日期：2026-10-25

现场只读检查发现，一个既有用户配置的 `symbology-style.db` 包含色带表但有 0 条色带；全新配置能从随程序提供的 `symbology-style.xml` 加载 35 条原生色带。QGIS 原生初始化对已有库采用加载/升级路径，不能依赖“创建新配置”修复已有空库，见 [QGIS 原生样式初始化实现](https://github.com/qgis/QGIS/blob/master/src/core/symbology/qgsstyle.cpp#L150)。

启动时，在原生窗口创建前读取随 QGIS 提供的默认样式，只把用户库缺少的色带持久化并加入默认样式对象。同名已有配色、自定义色带、符号和已有收藏不被覆盖。如果库中没有任何色带收藏，则补入原生默认收藏，让属性窗口下拉菜单能直接选择常用色带。缺少资源或无法写入时记录明确路径及原因，应用其他功能继续启动。

安装资源中的原生库提供 Viridis、Turbo、Spectral、RdBu、Blues、Magma、Plasma、Inferno 等 35 条色带。属性窗口沿用 QGIS 自身的色带选择、反转、分类和应用行为。两个便携包脚本都增加默认样式 XML 输入检查，防止发布漏掉符号与色带资源；不改变已有工程的渲染器和数据值。

验证使用隔离编译输出、测试配置与临时数据，未写入实际用户样式库，也未替换正在运行的程序：

- `tst_startupdatabases`：8 passed，0 failed；覆盖默认色带、空库补齐、自定义及同名配色保留、幂等、持久化重读、无收藏修复，及既有工程库启动检查。
- `tst_layerproperties`：15 passed，0 failed；真实栅格原生属性窗口的 Viridis 菜单入口、选择、反转、应用和非空着色分类列表检查通过，原有矢量/栅格属性与样式预设、QML 往返检查通过。
- 两个打包脚本语法检查通过；未实际运行完整便携打包或安装包交互验收。

更新构建后，程序启动会补齐既有空样式库，无需删除用户配置。
