# 地震层段批量井相重复预测（2026-11-03）

## 原因

已有预测会在维护表保存当前层段的分层行。再次从编图入口预测时，
`wellRequestEntry` 把这些维护行作为 `vector_formations` 带入；井相适配器随后
又加入当前方案修订的同名地震层段。返回值出现两份当前层段，发布端要求一份，
因此整批停在 95%，报笼统的“网格、井集合或微相编码与请求不一致”。
旧维护窗与方案窗不同，还可能错误地使用旧窗验收新预测。

新增回归在同一原生工程连续预测两次，修复前第二次稳定失败；首次成功的测试
此前未覆盖这个场景。

## 修改

- 当请求带有冻结的地震层段选择时，当前层段窗由该方案修订提供一次。
  历史维护行中的同名层段不再重复加入，也不能覆盖当前选择；其他组／段资料保留。
- 不改写已维护的解释深度，不删除历史成果。新预测图件的顶底仍来自当前冻结窗。
- 发布仍校验井数、身份、坐标、微相编码、单份当前层段及有效预测井段；
  失败提示区分分类／层段、井数、具体井身份／坐标／编码、井段范围和优势相统计。
  地震网格与迟到结果的拒绝规则保留。

## 验证与边界

- 用户工区按原配置真实服务只读复核，两个层段各 47 口曲线／井位齐全井：
  T30–T32/S1 返回 10 口有效预测，T70–T72/S1 返回 17 口；其他井带跳过原因。
  两批均为 27 类，身份、坐标、分类前缀、三级归属和深度边界检查通过。
- 同一批真实响应在独立临时工程重放成功，不向用户工区发布测试成果。
- 原生层段端到端回归覆盖首次、重复、维护窗已变化的三次预测；校验新图件使用
  方案窗，维护解释窗保持原值。另覆盖混合成功／跳过、整批失败／取消、无模型、
  空预测、非默认层位、优势相发布、坏响应及空地震网格拒绝。
- Windows 构建最多 8 workers。当前打开的 `tt3` 窗口有未保存修改，保留原窗口；
  修复版启动以独立首帧检查验证，既有窗口不会被强制关闭。
- 本次只修复重复层段导致的误拒，不把资料不足的井计为成功，不改变现有模型和
  层段内有效样点门槛，也不扩大预测范围。
