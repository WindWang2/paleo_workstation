# 连井剖面原生井入口与井震对齐（2026-11-03）

## 原因与修改

连井剖面和井震设置页原先用“曲线 + 可用时深”过滤整个井列表，
有曲线但时深元数据不足的井因此消失。此外，原生 XML 的多测井组还会走
文件路径索引，无法稳定读取 DataService 已保存的曲线。

- 选井入口按曲线资料列井，默认不勾选；缺坐标井保留查看但不能参与路线。
  每井分别说明时深资料存在情况与时间对齐能力，MD 井道不受时深条件阻挡。
- 原生曲线名从 DataService 元数据查询，数据体按井和测井组读取，保持声明的
  MD/m/ft 和原采样轴；归一为米后交给既有连井与地震井道流程。
  原生分层使用当前 DataService 分层读口，旧文件工程保留原兼容路径。
- 时深读取按原生井 ID 及显式选择的来源 ID 查询存储记录；来源无法匹配或
  多表歧义即诊断，不误走 Petrel 文本解析，也不替换用户选择的关系。
- 实际地震叠加仍需要有效本井时深和一致的时间基准；缺 MD/TVD 对照时不自动
  用 2500 m/s 补另一深度轴。已有显式常速设置不用于补齐缺失基准。
  时间平移、米/英尺、秒/毫秒、OWT/TWT 换算及表范围外不外推规则保持。
  设置页说明同步去掉自动常速叠加的旧提示。
- 旧文件工程的 TVD-only 时深关系按实际 TVD 轴判断可用性，结合已声明测斜
  精确换算 MD 分层位置，不再仅因没有 MD 时深列就把整井过滤。

## 真实工区只读验收

`tt3` 中 157 口井，64 口有曲线，47 口同时有井位。
连井候选和井震设置列表均返回 64 口，路线候选为 47 口；
HZ19-1-1A、HZ21-1-1 实际加载两口 MD 井道成功。
修复版原生窗口打开 `tt3` 后，连井／时深对齐对话框已显示井列表且没有默认勾选。

119 份已存时深关系的时间单位、时间基准字段缺失，所检查地震体的单/双程字段也
缺失。因此当前严格可对齐数为 0，实际请求如实报告缺失条件，不伪造井震对齐。
用户此前已确认地震及层位为 TWT/ms，但未确认 Petrel 时深的基准和符号，
本次没有写库、取绝对值、取反或猜测 MSL；时深口径操作面后续见 TODOS.md。
