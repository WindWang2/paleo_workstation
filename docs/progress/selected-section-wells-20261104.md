# 连井剖面保留所选井（2026-11-04）

用户截图显示标题选了五/六口井，图中只有两口。定位到四个相互独立的问题：

1. 地图吸附的井 ID 只被用来拼标题，没有传到剖面投影；按井序入口同样丢身份。
2. 井震候选沿用了“有曲线且有可反算时深”的分析门槛，把只有真实时深轨迹的井删掉；
   缺时深/缺空间轨迹的所选井连井名也不显示。
3. 一份真实时深表有不同 MD 对应相同 TWT 的观测。严格双向时深模型拒绝了整表，
   连原始 XYZ/TWT 轨迹也一起丢掉；这与“可以画观测轨迹”不是同一个条件。
4. 长剖面的末道中心落在 QRect 最后整数像素以右不足一个像素的位置，标签按整数
   right() 裁剪，导致末井仍消失。小体/短剖面每道大于一个像素时不易暴露。

## 修改

- 地图吸附和按井序入口将所选井 ID 与路径一起传到 dock/投影器；刷新标定后保留选择。
  剖面版本增加 `well_ids`，保存和恢复不再丢身份。旧版本没有该字段时沿用自动候选行为。
- SectionWorkbench 的分析选井列表仍要求曲线；空间候选独立按可定位井提供。
  只有时深轨迹而没有曲线的井可画井身，不能算出的曲线不捏造。
- 所选井保留井位标签。缺时深、恒定 XY 且无真实 Survey、或井身超偏距时标“仅井位”，
  悬停展示具体诊断；不拿默认速度或竖线代替。自动“最近 N 井”限制不裁掉显式选择。
  普通自动候选仍按既有偏距/空间门槛显示。
- 对严格递增 MD、非降序 TWT 且有时间跨度的已声明观测，保留实际 XYZ/TWT 轨迹。
  TWT 重复时不建立虚假的唯一逆函数，不给该分支生成曲线或层位反算输入；反向时间仍拒绝。
  不改变原始点、来源、单位、符号和时间零点。
- 标签接受一个像素以内的边缘位置并夹回最后可绘像素，保留原始 trace/距离坐标。
  没有把整个图外的井强行拉进视口。

Data_service 的现有类型化读口已经足够，本轮不改子模块。数据查询/几何校验在服务和
domain，工作流编排，视图负责标签和绘制；没有增加 QtWidgets 跨层依赖或基线余量。

## 验证

Windows 独立 build/threaded 构建，最多 8 并行；7 个相关套件串行通过：
`tst_seismicmapping`、`tst_sectionlifecycle`、`tst_sections_alignment`、
`tst_deviatedseismic`、`tst_inversion_native`、`tst_seismic_welltie`、
`tst_inversion_lowfreq`。覆盖选井信号传递、缺时深路线、曲线与井身能力分开、
重复 TWT 的观测保留/逆函数禁用、选择身份保存重读，以及原沿井计算回归。

像素回归用 3000 道的稠密显示重现末井不足一像素的边界；验证两口所选井的标记都出现，
即使自动井数限制为 1 也保留，同时图体内与无井背景逐像素一致，证明没有伪造井身。

实际 HY 副本按环境变量指定两组井重放（并非读取用户未保存窗口状态）：

| 组 | 原始剖面 | 所选井位 | 可显示观测井身 | 仅井位 |
|---|---|---:|---:|---:|
| 五井 | 1460×4096 | 5 | 3 | 2 |
| 六井 | 4406×4096 | 6 | 3 | 3 |

两个重放都读取真实地震振幅、生产 DataService 层位和生产 Canvas，逐口检查顶部标记像素。
六井组包含一口无曲线、22 个观测点且含重复 TWT 的真实轨迹，已保留井身。
其余仅井位是资料能力限制，不把它们画成已知直井。
