# TVD-only 井分层预览修复

2026-10-22。

问题原因：

- 综合测井图直接读取 WellTopRecord.md，忽略 hasMd。原表“顶界垂深”正常保存为
  TVD、MD 缺失；解析器的 MD 数值槽默认 0，视图把所有层段叠到 0 米，最后 D82
  覆盖前面层名。原始分层表本身已正确解析，不能通过批量填 MD=0 修复。
- 分层预览只用顶界，最后一层硬加 50 米；没有读取原表提供的底界。

修复：

- PreviewDocService 返回只读显示副本：已有 MD 优先，否则采用测斜反解或单调
  MD/TVD 对照。井口按 MD/TVD 定义补 0/0 锚点；非等深对照的深部范围外不自动外推。
  缺换算资料时按直井等深显示并说明，坏测斜或多解对照不悄悄回退。原始记录不改。
- 沿用该井已决分层来源选择、优先主分层，按有效显示 MD 排序，不把缺失 MD 当零。
- 从当前分层的 RAW 血缘读原始 Excel／文本底界，核对原件 SHA-256 和原顶界；
  原件变化、缺失或顶界已编辑时不套用旧底界。保持现有 TOPS 文件格式兼容，
  现有工程可直接重开预览，不要求重新导入。
- 有明确底界时保留真实厚度；否则使用下一顶界，末层只延至当前曲线末深。
  视图只负责颜色与区间装配，换算及原表查询在数据层。

验证：

- 使用用户 comp 工程的 SQLite 一致性快照和受管分层副本，源工程保持只读。
  20 口井共 516 条分层均可定位；A10／A19 按各自非等深对照换算。
- A1 共 27 层：D61 显示深度 1894 米，D82 按原表 2136–2160 米显示。
  真实 LAS、岩心图片及测井图截图复查通过，原始 MD 仍为空。
- 新增回归覆盖：TVD-only 综合图不塌缩、显式 MD 保留、对照插值、歧义对照拒绝、
  测斜优先、无测斜提示、底界解析，以及实际工程只读快照。
- 主程序独立构建通过，最多 -j8。import_preview 19、previewdoc 14、projectdata 7、
  wellfileparsers 61、projectsetup 定向 3，合计 104 通过，0 失败、0 跳过。
- 源码闸门通过，file-budget 的 buildWellLogContent 冻结值 263→238；
  其他基线无增长。
