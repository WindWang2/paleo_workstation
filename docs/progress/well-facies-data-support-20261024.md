# 测井微相数据支撑核验（2026-10-24）

## 验收口径

分别核对分类可识别、模型输入可准备、独立地质验证三项。类别名称存在、服务返回成功、
预测置信度高，都不能代替独立岩心/录井解释验证。本次未上传资料或调用远端推理，未修改
原始资料、历史预测或人工解释。

本机验收集包含20口井、8个编图层位。逐井读取LAS数据体、岩屑XLSX来源列，按汇总
单因素表的MD层界筛查128点连续GR及岩性窗口；这不是服务模型专项准备检查，不能
替代模型实际曲线、分类字段和窗口要求。补齐前LAS备份另作逐深度、逐值只读比对。

结果：

- 160个井层组合中149个具备上述窗口；10个缺少有效MD层界，A20/C3最长连续支撑96点。
  不向层外扩窗，不把TVD直接当MD，也不外推时深关系以凑齐输入。
- 20口井LAS均有显式合成输入注记；备份A8无正GR点，A13仅10个正GR点。
  同井替代、插值、邻井移植、GR推导岩性、生成分层不能算独立验证证据。
- A8 LAS头STEP为1，数据体中位步长为0.125；检查使用数据体实际采样。
- 历史井属性表的9类预测词面均能在默认27类中解析；历史井段数不等于独立样本数。
  远砂坝仅2个预测井段、涉及1井，沼泽沉积8段、涉及3井，尤其需要独立标注核验。
- 已按照片文件名显式米深度生成候选关联清单。关联尚须确认MD/TVD基准与人工解释，
  不把照片存在认作微相验证通过；无此类候选也不等于没有其他岩心/薄片资料。

原始路径、SHA-256、来源计数和候选照片清单只保留在本机核验产物，不入Git。

## 软件修复

1. 预测准备检查、单井工作流、批量编图和传输入口统一核对模型声明的**全部**微相，
   预先冻结完整三级归属及编码。未知、空、父级或同名歧义类别明确拒绝；项目已定义的
   自有完整微相可用。批量成果保存完整类别，编码不依赖本次实际返回哪些类别。
2. 回包必须属于该模型声明的类别；可接受解析为同一类别的别名，不能因为某类别存在于
   系统词表就接收模型未声明的结果。旧直达文件解析保留兼容入口；正式服务强制绑定。
3. 已受理任务的复用键补入模型版本、全部类别和冻结分类，避免换版后误复用旧任务。
4. 岩屑原表“数据来源”进入规范CSV、目录元数据与岩性来源文字；空来源保持未声明。
   LAS显式合成头注进入导入版本元数据，相同字节重导也补记该注记。
5. 编图血缘补入曲线实际来源版本与岩屑版本；派生成果继承合成输入标记，证据链逐输入
   记录来源并显示“含合成输入”。这与传输替身`mock`分开，真实服务也可能使用合成输入。

既有成果不做追溯性改写。旧规范岩屑CSV若已丢失来源，应以保留来源列的原表重新导入
后再生成；不能从缺标记推断历史结果全为实测。单井维护属性表仍按原有契约保留人工
解释和预测结果的区别，本次不新增地质标签或替换人工解释。

## 可重复核验

工具只读输入；输出须位于资料目录之外。运行完整核验需openpyxl，纯筛查单元测试
仅依赖Python标准库。

```powershell
python tools/audit_well_facies_inputs.py <资料目录> --output <核验输出目录> --baseline-logs <补齐前LAS目录>
python -m unittest discover -s tests -p test_audit_well_facies_inputs.py -v
```

产物包括`audit.json`、`well_horizon_coverage.csv`、`microfacies_support_candidates.csv`
及中文报告；照片候选CSV仅在存在匹配时输出。补齐前对照统计同时保留非空值、正值和
零值数量，不静默把所有零值当缺失。
