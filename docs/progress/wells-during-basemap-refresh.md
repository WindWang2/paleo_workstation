# 在线底图刷新期间保留井点与井名（2026-10-22）

测区全景的井位层并未被删除。原生整图渲染的标注阶段等待图层完成，
在线瓦片很慢时，井点和井名随整图一起延迟；独立的测区 rubber band
仍可见，因而表现为只剩范围边框。

在已有 `onlinebasemap` QGIS 封装中安装一次临时前景渲染器，主画布与
预览画布复用。存在可见底图选择时，另用 `QgsMapRendererParallelJob`
按同一地图设置、坐标转换上下文和可见矢量图层生成透明前景，符号与
标注仍由 QGIS 负责。前景不包含底图，不增加瓦片请求，也不登记额外
工程图层。透明展示不拦截地图操作；原生整图完成后撤下临时结果。

平移、缩放、旋转和图层切换立即丢弃旧结果，并重新绘制当前前景。
异步完成回调检查代次，过期结果不上屏；关闭画布取消临时任务。
打印、导出和原生完整渲染保持原有行为。

`tst_onlinebasemap` 使用独立线程中的本地 HTTP 服务，先允许 provider
初始化，再扣住实际视野的瓦片响应：分别验证延迟成功和 HTTP 503。
在响应尚未释放时，断言原生整图仍在绘制，而井点像素与井名像素已显示；
平移后断言新位置上屏、旧位置消失；释放响应后，临时前景撤下且原生
标注结果仍包含井名。测试不依赖公网或提供者的实际速度。

本机验证：`tst_onlinebasemap` 9 pass、`tst_basemap_rendering` 4 pass、
`tst_wellbasemap` 8 pass，共 21 pass / 0 fail / 0 skip（含初始化与收尾）。
独立 worktree 编译改动源码并链接同版本既有模块，应用 `--help` 退出 0；
源码分层、Qgs 审计、散布、规模、UI 不变量/token、i18n 和文档闸门通过，
未增加任何基线条目。本机启动程序已备份并更新，运行中实例正常退出后生效。

实现依据为本机 QGIS 头文件及同版本官方源码：
[并行渲染与标注阶段](https://github.com/qgis/QGIS/blob/final-4_2_3/src/core/maprenderer/qgsmaprendererparalleljob.cpp)。
