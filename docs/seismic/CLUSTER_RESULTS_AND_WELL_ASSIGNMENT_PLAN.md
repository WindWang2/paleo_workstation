# 地震原始聚类与井预测赋相实施方案

**状态**　已按本方案实施，原始基线为工作站 `d555220e`。操作入口见[层位编图工作台](../workflows/MAPPING_WORKBENCH.md)。

地质人员可以先回答“哪些区域的地震反射特征相似”，再决定“现有井资料支持把这些区域解释为什么微相”。建议在「地震相分析」交付两个可独立运行、可分别保存的操作。

| 操作 | 用户提供 | 完成后直接得到 |
|---|---|---|
| 运行地震聚类 | 地震体、层段或兼容层位、聚类数 K | 地图上的原始聚类栅格，以及可点选的聚类面。没有井预测、微相分类表或远端服务也能完成 |
| 用井预测赋相 | 一个已保存的原始聚类版本、同层段井预测、目标微相分类版本 | 先预览各簇的支持井与分歧，再保存一份井约束解释图。可换一批井重新赋值，直接复用原始聚类 |

## 1. 现有实现与改动位置

本地「地震层段窗聚类 → 微相图（Mock）」已经对真实反射窗的均值、RMS 和过零率做标准化与确定性 K-means。工作台用相表条目数决定 K，要求先有井预测。算法算出簇号后，工作台立即按井投票，用微相码覆盖簇号，再保存栅格并自动转相面。平票取较小相码，无井簇按固定种子从已出现的井相中抽取。多个簇可以得到同一微相，事后仅凭该相图无法恢复原分区。[工作台预测流程](../../src/workflow/mappingworkbench_predict.cpp) · [聚类内核](../../src/services/seismichorizoncluster.cpp) · [当前井票规则](../../src/services/seismicclusterlabels.cpp)

另有两个相关入口。远端微相预测直接返回地质相，沿用现有发布路径。属性融合客户端能返回有编号的原始簇网格，但还没有接入成果发布。本期先打通用户现在可操作的本地层段窗聚类，预留相同的原始成果格式给属性融合客户端。[工作流说明](../workflows/MAPPING_WORKBENCH.md) · [属性融合客户端](ATTRIBUTE_FUSION_CLIENT.md)

## 2. 第一步交付可复用的原始簇图

1. 用户选择地震体、层段和 K。K 作为独立参数传给两条取窗路径，沿用本地内核的 1–64 限制，有效样本少于 K 时给出实际样本数。当前工区使用冻结单元的顶底界，旧工程保留原始层位点或时间栅格的 ±12 ms 路径。保留缺道和缺测孔洞。
2. 聚类完成即登记原始 GeoTIFF 并显示。有效值为 `cluster_id=1..K`，图例显示“簇 1、簇 2……”及实际出现的簇。记录地震体版本、单元修订或层位快照、窗口、特征与标准化方法、K、有效覆盖、CRS、网格变换及算法版本。编号只在本次聚类版本内引用。
3. 随后从同一栅格生成 GeoPackage 聚类面。按四邻接划分同簇连通图斑，以斑块内最小的行优先像元序号生成版本内稳定的 `patch_id`，保存 `cluster_id`、像元数和原始栅格版本。精确边界、孔洞、单像元小斑都保留。成面失败时栅格仍可打开，支持单独重试。现有相面转面会平滑和合并小斑，留给后续制图使用。[转面编排](../../src/workflow/mappingworkbench_polygonize.cpp) · [转面算法](../../src/algorithms/faciespolygonize.cpp)
4. 用户点选面可看到簇号、斑块号并高亮同簇区域。原始图按簇号使用 QGIS 分类图例。井赋相或人工指定微相后，解释图使用相、亚相、微相的层级显示与地质图例。沿用现有 QGIS 视图、结果表和任务反馈。[界面设计约定](../../DESIGN.md)

## 3. 第二步用井预测给聚类面赋值

**建议首版默认按整簇赋值。** 在选定的原始图上，每口有效井只给它落入的簇投一票。同簇的多个不相连图斑共用一个解释。预览同时列“本斑块井数”和“全簇井数”，点选某个图斑即可看出它是由本地井支持，还是沿用同簇其他图斑的井证据。若业务要分别解释相离图斑，可在后续加入“按独立图斑赋值”，把计票键切换为 `patch_id`，并把赋值范围写入版本。

**井证据如何选取**

- 支持两类已保存的结果。工作台的井点成果直接读取该井的层内优势微相。单井相分析保存的分段预测 JSON 按井的目标层段顶底 MD 截取，复用按覆盖厚度求优势相的逻辑，每口井最多贡献一个相。两个来源在同一井汇合后再计票。层内无覆盖、厚度并列或文字无法唯一映射的分段结果列入待核对。[井点筛选](../../src/workflow/mockseismicinputs.cpp) · [单井成果格式](../../src/workflow/wellfaciesworkflow_unit.cpp) · [优势相计算](../../src/algorithms/faciesmapping/formationdominance.h)
- 按工程井身份、地层方案、层段/子层段、聚合方式及有效几何修订匹配。多井筒或重复层段先核对井筒和层段出现记录，归属不唯一时提示核对。旧层位工程沿用已登记的层位对应关系。默认按目录登记顺序取该井最新的匹配版本，再判读预测状态，同一井的新记录标为未预测时屏蔽旧票。用户显式选择时冻结所选版本集。全井汇总、未保存记录和过期输入均有明确的排除原因。历史分类依据冻结的“相／亚相／微相”完整路径匹配到目标分类。
- 沿用快照摘要校验和 CRS 转换。井点取成果记录的平面位置，单井 JSON 通过井身份取得已验证的井口坐标，注明井口投影。旧工程的局部坐标需与数据底座的井位逐井核实。井落在哪一簇由**原始栅格**决定，使用北向上网格、行列向下取整、左和上边界包含、右和下边界排除。范围外或落在 NoData 的井单列，不计票。选定快照损坏、坐标或分类无法可靠对齐时列明问题，修正或重新选择后才能保存解释。[井预测校验与坐标转换](../../src/qgis/seismicwellcalibration.cpp)

**建议新操作采用以下规则。** 预览列出每个簇的各相票数、井名、井预测版本和支持率。支持率取该相票数除以簇内有效票数，表达本批井的一致程度。

| 簇内证据 | 预览与保存 |
|---|---|
| 一个相超过半数有效井 | 写入目标微相及其上级分类。仅一口井时标“单井支持” |
| 平票或最高票未过半，如 2∶1∶1 | 标“有分歧”，保留票数，微相留空 |
| 整簇无有效井 | 标“无井支持”，微相留空。整个输入集均未落入有效簇时，仅给诊断和原图入口 |
| 地震无有效像元 | 维持 NoData，无聚类面、无赋相记录 |

例如簇 3 有两个相离图斑。西侧三口井分别预测为河道、河道、河口坝，东侧没有井。按整簇赋值时，两面均赋为河道。点选东侧显示“本斑块 0 井，全簇 3 井，河道 2/3”。另一个簇若两口井各投一相，就保持“有分歧”。

### 人工调整相解释

首版支持从原始聚类面直接指定微相，也支持在井预测赋相后修改。用户从项目分类表选择目标微相，可以应用到整簇，也可以只改选中的图斑。例如解释人员判断东侧图斑属于河口坝，就只改东侧，西侧仍显示河道。需要修边时，可在解释图上沿用矢量编辑工具调整相面边界。

提交前高亮受影响的面并显示数量。保存时另建解释版本，记录来源聚类、调整范围、井预测建议值（如有）和人工最终值，修改说明可留空。重新计算井票时另存建议，已保存的人工解释可继续使用，也可与新建议对照。

## 4. 数据产品与模块分工

| 成果 | 保存内容与版本关系 |
|---|---|
| 原始簇栅格、精确聚类面 | 在目录使用专门的成果类型。栅格的父来源为地震体及层段几何或层位文件，聚类面指向该栅格。相表和井预测不进入聚类依赖 |
| 井赋相面、派生微相栅格 | 赋相面完整保留原几何、`patch_id`、`cluster_id`，新增可空的 `facies_code`、赋值状态、本面及全簇井数。栅格沿用原网格，仅有解释像元输出有效相码。查阅“待定”与“地震缺测”的区别，以赋相面状态和原栅格掩膜为准 |
| 赋值证据 | 随赋相版本冻结计票范围、规则、分类版本、来源井版本、参与或排除原因、每簇票数与支持井。赋相成果共同引用这份证据和精确聚类版本。更新井预测可生成新的解释，历史结果可原样重开 |
| 人工解释面 | 从原始聚类面或井赋相面派生，引用来源版本，并记录每个改动对应的簇号、图斑及最终微相。地图和导出均使用选定解释版本的边界与相值 |

数据层负责簇编号、连通标识、井证据和计票规则。QGIS 封装负责空间读写、坐标转换与分类渲染。工作流负责冻结输入、后台任务、预览和版本发布。视图只传选择、显示结果。沿用 D 盘工程的目录、同卷暂存和版本登记机制，以工程相对路径引用成果。赋相发布按一次操作提交；取消、切换工程或写入失败时清理本次暂存，保留可用的原始聚类。[项目架构](../PALEO_QGIS_PLAN.md) · [数据模型与 I/O 方案](../architecture/DATA_MODEL_IO_IMPLEMENTATION_PLAN.md)

发布与消费按成果类型显式分流。原始类型跳过通用登记中的自动补相表、相面编辑器和地质图例。数据底座、编图底图和井震一致性检查只把有明确地质类型的成果作为相图消费。旧 `seismic_prediction`、Mock 标记、相表和历史投票记录按原版本读取。要得到遗留工程的原始簇图，可用原地震与层位重新计算。实施时同步修订设计文档中旧 Mock 的强制先井、平票及随机补相约定，并更新操作说明。[通用成果登记和渲染](../../src/workflow/mappingworkbench.cpp) · [底座投影](../../src/workflow/analysisresultsync.cpp) · [编图底图](../../src/workflow/mappingbasemaps.cpp) · [井震一致性](../../src/workflow/mappingworkbench_consistency.cpp)

## 5. 实施顺序与 Windows 验收

| 批次 | 可独立验收的交付 | 关键用例 |
|---|---|---|
| 1 · 原始聚类 | 独立运行入口、K 参数、簇栅格及精确簇面、工程重开 | 空井库和空相表也能出图。固定输入与 K 复现像元值。两条取窗路径均保留覆盖、孔洞、对角分离及单像元斑块。成面重试不重算地震 |
| 2 · 井赋相 | 两类井成果适配、预览、赋相图与证据 | 同簇多面、不同簇同相、单井、2∶1、平票、无票、范围外、边界和缺测。两种来源同井只投一票。不同子层段、错井或过期成果无法串入。新井版本只改变新赋相结果，原始栅格文件摘要相同 |
| 3 · 人工调整与集成 | 整簇改相、单图斑改相、修边、版本对照、目录与底座分流 | 无井也可人工赋相。同簇两个图斑可只改一个，整簇修改则预览两个。修边、换井重算、关闭重开后，能分别查看原始簇图、井建议和人工解释。原始簇不参与相一致性检查。验证三级图例、远端微相、输入变化、取消及写入失败 |

实施时在 Windows 原生环境使用仓库管理的依赖编译，构建最多 8 路、CTest 串行。改写原来断言“缺井拒绝聚类”和“无井簇随机赋相”的用例，运行地震聚类、映射工作台、分析单元与底座同步测试及源码门禁，传入仓管 QGIS 前缀补跑传递依赖检查。最后在 D 盘独立测试工程走通“无井出图 → 加井赋相 → 换井版本重新赋相 → 关闭重开”，核对像元、斑块、票数与版本关系。[聚类回归](../../tests/tst_seismichorizoncluster.cpp) · [工作台回归](../../tests/tst_mappingworkbench.cpp) · [层段集成](../../tests/tst_mockseismicunit.cpp) · [底座同步](../../tests/tst_analysisresultsync.cpp)
